# ADR-010: CSV와 시트 편집을 통합한 일괄 입력

- 상태: 채택 — 구현·관련 수용 검증 완료
- 결정일: 2026-10-25
- 관련: D-01·D-05·D-08·D-09·D-11~D-13, C-05, T-031~T-033
- 구체화: [ADR-008](ADR-008-bulk-entry-backlog.md)의 구현 시점·통합 방식·기술 설계

## 범위와 우선순위

사용자의 명시적 재개·실행 요청으로 T-019와 T-021의 실행 가능한 초기 통합·지정 시연 뒤 T-031~T-033을 구현한다. T-001/T-021의 외부 실환경 조건은 일괄 입력의 독립 작업을 막지 않는다. T-022~T-030·전체 운영 원자료 이관·자동 배포는 추가하지 않는다. ADR-007의 운영·원가 규칙은 유지한다.

## 선택

세 티켓을 `/bulk`의 공통 편집표로 통합한다. CSV 양식을 내려받아 작성/업로드하거나 같은 표에 직접 입력하고, 업로드한 셀을 수정한 뒤 최종 확인본을 등록한다. 세 화면을 따로 만들면 검증·재시도 상태가 중복되며, 범용 스프레드시트나 새 batch writer는 현재 요구보다 크다.

초기 파일 형식은 UTF-8 CSV다. Excel에서도 CSV로 저장하여 사용하며 `.xlsx` 파서는 추가하지 않는다. 파일/붙여넣기는1MiB·200행으로 제한한다. 인용부호·쉼표·줄바꿈과 BOM을 처리하고 잘못된 구조·미지/중복 열은 쓰기 전에 거절한다. 다운로드 예제는 가상 자료다.

재료는 이름·단위·종류·설명을 등록한다. 메뉴는 그룹별 기본 정보·기준 개수·선택 판매가와 여러 구성 행을 기존 레시피 writer로 등록하며 구성0도 허용한다. 입고는 품목 UUID·버전·실수량·단위·구입금액·입고일·메모와 기존 실사 포함 선택을 사용한다. 이름으로 자동 병합하거나 가상 재고를 만들지 않는다. 빈 값과0, 입력 시각과 입고일을 구분한다. 정확한 열 정의는 공통 양식/도움말과 [구현 계획](../tickets/T-031-T-033-plan.md)을 따른다.

## 확인·부분 성공·재시도

편집은 실제 입고나 확정 데이터에 반영하지 않는다. 등록 전 형식·필수값·참조·단위를 전체 검사한다. 입고는 기존 계산을 재사용한 읽기 전용 미리보기로 실제 수량·가치 효과를 확인한다. 각 입고의 미리보기는 그 상태의 독립 결과이며 배치 전체의 가상 미래 상태로 표시하지 않는다.

등록은 기존 재료/레시피·업무 초안/미리보기/확정 API를 순서대로 사용한다. 전체 배치를 단일 트랜잭션이라고 설명하지 않는다. 진행 중 실패하면 성공 행과 결과 링크를 보존하고 해당 행에서 멈춘다. 미리 본 입고 효과가 달라지면 새 효과를 표시해 명시적으로 확인받고 이어간다. 같은 품목의 정상적인 여러 입고나 포함 몫 분할을 임의 합산·삭제·금지하지 않는다.

전송 전 UUID·본문을 탭 저장소에 보존한다. 통신 불명 요청은 원본문으로 확인하며 성공 행은 재전송하지 않는다. 버전/세대 충돌에서 본문·참조를 자동 교체하지 않는다. 복원 뒤 처리된 요청은 다시 적용하지 않는다. 동일 내용 재업로드는 탭에 남은 실행 결과와 연결하거나 경고하고 명시적인 새 입력과 구분한다. 브라우저 임시 보관은 서버의 영구 파일 중복 원장을 뜻하지 않으며 앱 재실행으로 주소가 바뀌면 실제 목록을 먼저 확인한다.

## 저장·보안·되돌림

새 DB 스키마·직접 적재 경로·외부 서비스·의존성을 추가하지 않는다. 기존 버전·JSON·원요청·복원, API별 본문 상한(일반16KiB·레시피256KiB), 정확한 세션/Origin 검사를 유지한다. 새 입고 읽기 전용 미리보기는16KiB다. CSV의 HTML·수식 모양 문자열을 실행하지 않는다. 개인 운영 자료와 시연 산출물은 공개 코드·시험·정적 자산에 넣지 않는다.

소스 변경의 되돌림과 이미 확정된 업무의 되돌림은 구분한다. 확정 자료는 기존 정정/전체 복원 계약을 사용하며, 성공 행을 지워 배치를 원자 처리한 것처럼 만들지 않는다. 실행 검증·한계와 RTD는 세 티켓의 공통 계획/검증에 기록한다.
