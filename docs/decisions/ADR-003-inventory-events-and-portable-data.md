# ADR-003: 입력 시점별 재고·원가와 이동 가능한 데이터

- 상태: 채택 — 기본 요구사항 유지, 운영 예외는 [ADR-004](ADR-004-inventory-exception-policies.md)에서 추가 확정, 구현 전
- 결정일: 2026-10-24
- 관련: C-01~C-05, D-01~D-05, D-08~D-13
- 이전 기록: [ADR-002](ADR-002-first-release-and-local-storage.md)의 손질 수율 선택·날짜별 마감·DB 및 JSON의 직접 인접 보관을 대체하고 나머지 개발 단계는 유지한다.

## 배경

사용자는 단일 PC에서 식당 재고를 관리하고 실제 계량·현재고 입력으로 업무를 단순하게 처리하려 한다. 문서에서 다시 제시한 수율 선택, 영업일 마감, 네트워크 공동 사용 등의 가정을 바로잡았으며 마감 판매·폐기와 일괄 재고검사 흐름을 추가했다.

## 확정한 업무

1. 초기에는 단일 PC를 사용한다. SQLite DB 또는 JSON을 옮기면 다른 PC·Mac의 호환 빌드에서도 동일 데이터를 사용한다.
2. 발주·입고는 kg·L 등 실제 수량을 직접 입력한다. 입고 시 계량한 수량과 금액을 재고에 반영한다.
3. 과거 입고일을 사용자가 지정할 수 있다. 예: 무 3kg, 30,000원, 입고일 2026-10-24. 실제 입력 시각은 별도로 자동 기록한다.
4. 손질은 마감 재고정리에서 원물을 차감하고 실제 확보한 손질재료를 추가한다. 기준 수율 계산은 사용하지 않는다.
5. 마감에는 메뉴 판매 개수와 지정 재료의 폐기를 기록한다. 판매는 해당 메뉴 레시피 사용량을, 폐기는 입력 수량을 차감한다.
6. 확인한 품목만 현재고를 입력하고 나머지는 장부값을 유지한다. 일괄 검사도 지원하며 판매·기록된 폐기 반영 후 실제가 더 적으면 차이를 자동 폐기로 기록한다.
7. 입력 시점별 이력·시계열 그래프를 사용한다. 입고일 외의 날짜 지정과 영업일 마감·재개방 절차는 요구하지 않는다.
8. 보유 재고 평균 원가를 적용하고 재료의 현재 단위당 가격을 표시한다. 손질 후에도 투입 원가 총액을 결과물에 유지한다. 설명용 무 3kg·30,000원이 손질 후 2kg이면 100g의 메뉴 원가는 1,500원이다.
9. 실사 부족분의 폐기 손실은 남은 재고에 배분하기로 사용자가 선택했다. 10kg·100,000원에서 실제 8kg이면 2kg 자동 폐기, 총원가 100,000원 유지, 1kg당 12,500원이다.
10. 판매·가격은 메뉴 1개 단위다. 소·중·대는 별도 메뉴로 만들고 복제본에 `(2)` 형식의 이름을 붙여 독립 수정할 수 있게 한다.
11. 취소·반품은 해당 수량과 구입에 사용한 금액을 차감하는 동일 흐름이다. 실제 계상된 재고·금액을 대상으로 하며 존재하지 않는 미입고 재고를 차감하지 않도록 검증한다.
12. 직원식은 폐기 포함 임의소진으로 처리한다. 부분 입고·보관 위치는 백로그, 소비기한 추적은 제외한다. 초기 자료 이관은 별도 요청 때 다룬다.

## 파일·기록·복원

- 바이너리 하나와 그 옆의 `db/` 폴더 하나로 실행한다.
- SQLite DB·JSON 기록·고유명칭 사진 등 자산은 모두 `db/` 안에 둔다. 바이너리와 같은 폴더에 DB·JSON을 직접 두던 이전 결정을 대체한다.
- 데이터 변경마다 JSON 기록을 남기고 무기한 보관한다. 복원은 선택한 기록의 전체 상태로 현재 데이터를 되돌린다.
- 사진은 해시 등 고유명칭으로 보관하며 사진까지 이동할 때는 `db/` 폴더를 함께 가져간다.
- 비밀번호 잠금은 없다. 서버 이관은 안정화 이후의 계획으로 유지한다.

## 일괄 재검사 보충 · 2026-10-24

위 확정 결정을 유지한다. [일괄 재검사](../REQUIREMENTS-AUDIT.md)에서 축약된 검색·조회·화면 요구를 보완하고, 전량 폐기·초과 재고·지연 입고의 소급 계산·정정 흐름을 [O-01~O-04](../REQUIREMENTS.md#확정한-운영-예외)로 분리했다. 재검사 당시에는 제안이었으나 같은 날 사용자 승인으로 네 항목 모두 확정됐다. 채택 내용은 [ADR-004](ADR-004-inventory-exception-policies.md)를 따른다.

## 영향과 남은 구현 설계

수량 감소와 원가 감소를 동일하게 취급하지 않는다. 정상 사용은 해당 사용 원가를 차감하지만 손질은 원가를 이월하고 폐기 손실은 잔량이 있으면 잔존 재고에 배분한다. 전량 폐기 종료는 ADR-004를 따른다. 이미 반영한 판매·폐기·손질을 실사 차이로 이중 반영하지 않는다.

전량 폐기·실사 초과·지연 입고·정정은 ADR-004의 확정 O-01~O-04를 적용한다. 품목 ID, JSON 스냅샷/변경 기록 형식, 저장·복원 정합성, 다중 결과물·반품 차액의 계산안, OS별 빌드와 스키마 호환성은 기술 설계로 제시한다. 운영 요구가 확정된 항목을 다시 미결정 질문으로 되돌리지 않는다.
