# ADR-008: 파일·시트 일괄 입력 세 방식의 백로그 등록

- 상태: 채택 — 세 항목의 백로그 등록, 구현 착수 전
- 결정일: 2026-10-25
- 관련: D-01·D-05·D-08·D-09, C-05
- 근거: 파일 업로드형·시트 직접 입력형·업로드 후 편집 통합형을 각각 등록해 달라는 사용자 요청

## 문제와 제약

재료·메뉴와 입고 정보를 여러 건 입력하는 방식을 백로그에 보존한다. 입고에는 재료별 실제 수량·구입금액 등이 필요하며 기존 단위·입고일·재고·원가·기록 정책을 따른다.

## 검토한 방식과 결정

| 티켓 | 사용자 요청 흐름 |
| --- | --- |
| [T-031](../tickets/T-031-file-bulk-import.md) | Excel 또는 CSV 예제 양식 다운로드 → 재료·메뉴·입고 정보 작성 → 업로드 → DB에 추가할 내용·형식 확인 → 등록 버튼으로 일괄 등록 |
| [T-032](../tickets/T-032-sheet-bulk-entry.md) | 파일 없이 시트형 화면에서 직접 여러 행 입력 → 확인 → 일괄 등록 |
| [T-033](../tickets/T-033-editable-import-preview.md) | 두 방식의 통합안: CSV 업로드 → 확인 화면에서 데이터 직접 수정 → 수정 결과 확인 → 일괄 등록 |

세 항목을 별도 백로그로 등록한다. T-033은 통합 후보이며 T-031·T-032를 먼저 각각 구현해야 한다는 순서를 확정하지 않는다. 우선순위·구현 시점·최종 통합 여부는 착수 때 정한다.

## 영향과 남은 결정

1차 실행 순서와 ADR-007의 운영 정책은 유지한다. 재료·메뉴 정보 등록만으로 실제 입고를 만들지 않으며 입고 확정은 기존 수량·가치 반영과 지연 입고 중복 방지 정책을 따른다. 등록 전 확인·편집은 업무 확정과 구분하고 기존 저장·JSON 기록·재시도 원칙을 유지한다.

정확한 파일 형식 지원 범위, 열 구성·메뉴/재료 참조 연결, 중복 판정·재업로드, 오류 행의 전체/일부 등록 정책은 미정이다. 특정 과거 자료의 정제·초기 이관과 앱 검증을 거치지 않는 직접 DB 주입은 포함하지 않는다(C-05).

방식 선택이나 범위가 바뀌면 후속 결정에서 대체 관계를 남기고 세 티켓·요구사항·TODO·연결 기획 노트를 함께 갱신한다. 현재는 문서만 추가하며 앱·DB 변경이나 데이터 적재는 수행하지 않는다.
