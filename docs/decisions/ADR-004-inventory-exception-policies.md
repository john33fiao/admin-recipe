# ADR-004: 재고 운영 예외 네 가지 확정

- 상태: 채택 — 운영 정책 확정, 구현 전
- 결정일: 2026-10-24
- 근거: 사용자가 재검사에서 남긴 네 항목을 모두 권장 방향으로 진행하도록 승인했다.
- 관련: O-01~O-04, D-02~D-04
- 이전 기록: [ADR-003](ADR-003-inventory-events-and-portable-data.md)의 기본 운영·저장 결정을 유지하고 미확정으로 남겼던 운영 예외를 확정한다.

## 결정

기본 범위와 정상 처리 규칙에 더해, 사용자가 2026-10-24에 O-01~O-04의 권장 방향을 모두 채택했다. 아래 네 정책은 **확정 사항**이다. 기술스택 인터뷰에서 다시 선택받지 않고 구현·검증 기준으로 사용한다.

| ID | 항목 | 확정 처리 |
| --- | --- | --- |
| O-01 | 지연 입고 | 실제 입고일과 입력 시각을 별도로 보존하고 현재 입력 시점에 반영한다. 과거 판매·원가를 소급 재계산하지 않는다. 이미 지난 실사에 포함된 수량은 중복 추가하지 않고 현재 상태를 보정한다. |
| O-02 | 전량 폐기 | 잔량이 0이면 남은 원가를 전량 폐기 손실로 별도 기록하고 현재 재고 금액을 0으로 만든다. 이전 손실을 다음 입고에 넘기지 않는다. |
| O-03 | 실사 초과 | 누락 입고·전환·오입력을 먼저 확인한다. 원인 불명 증가는 기존 단가를 적용한 재고 조정으로 기록한다. 적용할 단가가 없으면 금액을 확인한 뒤 확정한다. |
| O-04 | 오입력·재고 부족 | 원기록을 보존하는 취소·정정 흐름을 사용한다. 미완성·재고 부족 입력은 임시 저장하고 누락 입고·손질 등 원인을 해결한 뒤 확정한다. 임시 기록은 확정 재고·원가에 반영하지 않는다. |

실사한 10kg에 이미 포함된 과거 입고 3kg을 늦게 등록해도 현재고를 13kg으로 만들지 않는다. 지연 입고 보정과 취소·정정은 현재 시점의 이력으로 남기며 날짜별 마감 재개방은 도입하지 않는다.

품목 ID, 같은 차원의 단위 환산, 소수 정밀도, 메뉴 복제 이름 충돌, JSON 파일 구조·저장 정합성·사진 보존, DB 이동 절차와 위 정책의 구체적인 보정 알고리즘은 기술 설계 항목이다. 여러 손질 결과물·반품 차액도 확정한 원가 원칙에 맞춰 계산안을 만들고, 실제 사례가 그 원칙으로 설명되지 않을 때만 새 판단을 요청한다.

## 영향과 검증 기준

- 지연 입고: 과거 판매·원가 이력을 바꾸지 않으며, 이미 실사에 포함된 수량을 중복 증가시키지 않는다. 보정 수량·금액과 원기록 연결 방식은 기술 설계에서 구체화한다.
- 전량 폐기: 2kg·30,000원을 전부 폐기하면 보유량 0, 보유 원가 0, 별도 손실 30,000원이다. 이후 1kg·12,000원을 입고하면 신규 재고 원가는 12,000원이다.
- 실사 초과: 누락 기록이 없고 장부 10kg·100,000원, 실사 12kg이면 기존 10,000원/kg을 적용해 조정 +2kg·+20,000원, 보유 원가 120,000원으로 기록한다. 원인이 확인된 경우에는 해당 입고·전환·정정을 먼저 처리한다.
- 임시 입력: 확정 전에는 보유량·원가를 변경하지 않는다. 확정 후 동일 기록의 재저장으로 중복 반영하지 않으며 원기록과 정정 연결을 보존한다.
- 잔량이 남는 폐기의 기존 원가 배분 규칙은 유지한다. 전량 폐기만 위 종료 규칙을 적용한다.

이 기준은 문서상의 수용 사례이며 실제 앱 테스트 통과를 뜻하지 않는다. 기술스택·OS별 빌드·데이터 구조·복원 구현은 다음 단계다.
