# 구조·기술 결정 현황

## 현재 상태

앱 코드와 런타임 설정은 아직 없다. 직접 개발하여 소스코드를 공개한다. [ADR-002](decisions/ADR-002-first-release-and-local-storage.md)에서 초기 개발 범위와 저장·배포 방향을 정했다.

## 확정한 경계

- 초기 사용자 맥락은 셰프 1명의 식당 운영이다.
- 1차는 레시피·원가·발주·입고·판매·재고, 2차는 내일 메뉴 계획·작업시간, 시설 점검은 백로그다.
- 업무 구조는 원물 → 손질 → 비축메뉴 → 판매메뉴다. 판매 전 주방의 식재료·음식은 재고로 관리한다.
- 웹 UI 기반 설치형 앱을 단일 바이너리로 배포한다.
- 기본 데이터는 로컬 SQLite, 백업은 JSON 파일을 사용한다. DB 파일과 JSON 백업 파일은 모두 실행 바이너리와 같은 폴더에 보관한다.
- 저장 위치는 실행 바이너리가 있는 디렉터리를 기준으로 한다. 실행 당시 작업 디렉터리가 달라도 같은 DB·백업 위치를 사용한다.
- 안정화 후 별도 서버를 마련해 데이터와 서비스를 이관한다.
- PC·태블릿·모바일 화면과 라이트·다크 요구는 유지한다. 초기 설치 대상과 기기 간 연결 방식은 아직 정하지 않았다.
- 공개 소스코드·개발 문서와 실제 운영 데이터는 분리한다. 예제·테스트에는 가상 데이터를 사용한다.
- 프로젝트 코드와 직접 작성한 문서에는 [MIT 라이선스](decisions/ADR-001-mit-license.md)를 적용한다.

## 남은 기술 결정

| 영역 | 남은 판단 |
| --- | --- |
| 업무·데이터 | 단계별 식별 구조, 단위·원가, 재고 차감 시점, 마감·정정 이력과 수용 기준 |
| 설치·실행 | 대상 OS·아키텍처, 웹 UI 실행 방식, 바이너리 구성·업데이트 방법 |
| 로컬 저장 | SQLite 스키마·버전 변경, DB 파일명, 사진 저장 위치·형식 |
| JSON 백업·복원 | 파일명·데이터 범위·버전·사진 포함, 자동화·주기·보존 기간, 복원·정합성 검증 |
| 기기·접근 | 태블릿·모바일 이용 방법, 기기 간 공유, 외부 접속, 로컬 인증·잠금 여부 |
| 서버 이관 | 안정화 판단 기준·전환 시점, 서버 환경·인증·권한, 데이터 이관·검증 절차 |
| 구현 | 언어·프레임워크·라이브러리·패키지・빌드 및 검증 도구 |

단일 바이너리는 배포 형태에 대한 결정이며 특정 언어·프레임워크나 모든 OS에 공통인 실행 파일을 뜻하지 않는다. SQLite 채택이 사진을 DB에 저장하거나 기기 간 자동 동기화를 제공한다는 뜻도 아니다.

## 이전 후보와 적용 범위

파일 업로드·다운로드, 경량 호스팅, 정적 웹과 외부 저장소, NAS·컨테이너 구성은 이전 검토 후보였다. 초기 구현은 로컬 설치형을 기준으로 진행한다. 서버 전환 시 후보를 다시 비교할 수 있으나 현재 특정 호스팅을 채택하지 않았다.

변경 결정은 [결정 기록](decisions/README.md)에 남기고 관련 요구사항·TODO·기획 노트와 함께 갱신한다. 실제 앱 코드가 생기면 README와 RTD에 실행·검증 명령을 추가한다.
