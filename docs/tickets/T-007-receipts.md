# T-007: 실측 입고와 보유 평균 원가

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-02, D-02·D-04~D-05, P-03~P-07
- 선행: [T-006](T-006-purchase-orders.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

구매 수량과 실제 금액을 반영해 현재 보유량·가치를 계산한다.

## 포함 범위

직접 입고와 주문 연결 입고, 실제 수량·구입금액·입고일 입력, 현재 평균 원가와 입고 이력 조회를 구현한다.

## 제외 범위

배송비·세금 자동 배분, 부분 입고 추적, 지연 입고 금액 보정 자체.

## 수용 기준

- [ ] T-007-01: 발주 없이 직접 입고하거나 미입고 주문에 연결한다. 주문량과 실입고량은 별도로 보존한다.
- [ ] T-007-02: 과거 입고일을 지정하고 입력 시각은 자동 기록한다. 미래 입고 예정은 실제 입고와 구분한다.
- [ ] T-007-03: 호환 단위를 환산하여 실수량과 구입금액을 확정 재고 변동에 반영한다. 실사 화면에는 마지막 확인 수량·시각과 이후 확정 입출고를 구분한다. 건별 단가의 단순 평균을 사용하지 않는다.
- [ ] T-007-04: 0원 입고를 유효하게 처리하고 미입력 금액과 구분한다. 원가 출처·마지막 유효 단가를 갱신한다.
- [ ] T-007-05: 이미 실사에 포함된 지연 입고는 일반 입고와 구분해 임시 보관·안내하고 수량을 다시 더하지 않는다. 보정 확정 기능은 후속 T-011에서 완성한다. 이 티켓의 완료에 후속 보정 기능 구현을 요구하지 않는다.
- [ ] T-007-06: 가상 1kg·10,000원과 2kg·40,000원 입고 후 3kg·50,000원이며 단가는 계약 정밀도로 50,000÷3원/kg이다.

## 검증 방법

호환 단위·0원·가중 평균·주문 종료·날짜/시각 분리·중복 재시도 저장/API/UI 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
