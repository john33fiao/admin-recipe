# T-001: Rust·Nuxt 휴대 실행 검증과 첫 저장 흐름

- 상태: 진행 중 — Windows x64 후속 검증·최신 macOS ARM64 재검증, 필수 실환경 기준 미충족. OS 간 데이터 왕복 검증은 백로그
- 작성일: 2026-10-24
- 관련: D-10~D-13, C-01, D-05, [ADR-005](../decisions/ADR-005-rust-nuxt-local-server.md)

## 목표와 범위

Rust 서버에 Nuxt 정적 UI를 내장한 OS별 바이너리의 실행·종료·데이터 보존을 먼저 검증한다. 첫 업무 흐름은 재료의 이름·관리 단위 등록 → 저장 → 목록·상세 조회로 구현했다. 검증에는 가상 자료만 사용한다. 재고·원가 전 기능, Electron·자동 업데이트·서버 배포·초기 자료 이관은 포함하지 않는다.

2026-10-24 후속 사용자 결정(D-12·D-13)으로 Windows↔macOS 데이터 왕복 검증만 [백로그](../TODO.md#백로그)로 이관했다. OS 간 데이터 이동 지원 목표는 유지한다. 현재는 각 환경의 정상 동작과 같은 OS의 경로 이동을 검증하며, 왕복 검증은 완료의 필수 차단 조건에서 제외한다. 다른 미검증 수용 기준은 유지한다.

## 착수 전 설계

[구현·검증 계획](T-001-plan.md)과 [채택 구현 ADR-006](../decisions/ADR-006-local-runtime-and-journal.md)을 따른다. 아래 검토 항목을 구현과 검증에 연결했다.

- 권장 라이브러리·도구 버전, 지원 OS·아키텍처·브라우저 검증 목록과 빌드 순서를 정한다.
- 품목 ID·관리 단위와 스키마 버전, 변경 기록의 JSON 형식·버전, 저장 완료 의미·실패 복구를 정한다. 수량·원가를 추가하는 티켓에서는 단위·정밀도 및 O-01~O-04 알고리즘을 선행 설계한다.
- heartbeat의 초기 대기·Ping/Pong·복수 연결·재연결·절전 복귀·안전 종료 상태를 정한다. ADR의 시간값은 검증용 제안이다.
- 사진을 포함한 전체 복원·OS 간 이동과 과거 DB·JSON 호환은 별도 설계/검증 묶음으로 연결한다. T-001의 작은 저장 흐름만으로 전체 복원을 완료 처리하지 않는다.

## 구현 메모

Nuxt 정적 UI 생성 후 입력·산출물 해시를 기록하고 Rust release에 내장한다. Axum·Tokio 서버, bundled SQLite, 요청 UUID와 JSON 기록 대기열, 단일 작성자 잠금, 서버 Ping/Pong·종료 유예를 구현했다. 라이브러리·파일·호환·오류 의미는 ADR-006을 따른다.

## 검증 결과

2026-10-24 macOS ARM64의 초기 결과를 보존하고 Windows x64에서 후속 빌드·저장 장애·합성 마이그레이션·실제 TCP/WebSocket·브라우저 검증을 수행했다. 초기 macOS 결과는 당시 Windows 후속 변경의 회귀 증거로 사용하지 않았다. 이후 현재 Mac에서 최신 소스를 다시 빌드하고 Rust 36개·프런트엔드 3개·Chromium E2E 6개와 권한·프로세스 종료 검사를 통과했다. 명령·환경·수용 기준별 결과와 변경 후 검토는 [검증 기록](T-001-verification.md), 발견·조치·잔여 위험은 [보안 검토](T-001-security.md)에 있다.

**완료 처리하지 않는다.** T1-02의 개발 도구 없는 별도 Windows/Mac 배포, T1-06의 실제 절전·브라우저별 복귀 등 필수 검증이 남아 있다. T1-10의 OS 간 데이터 왕복은 위 사용자 결정에 따라 백로그로 보류하며, 같은 OS 경로 이동 검증은 유지한다. 사진·과거 JSON 전체 복원과 실제 정식 이전 버전 DB는 후속 범위다.

후속: 품목/전환 모델, 수량·금액 정밀도, 원가·정정·지연 입고 보정, JSON 재생과 사진을 포함한 전체 복원, 이전 정식 버전별 회귀 fixture. 이 목록은 이번 요청에서 새 티켓으로 구현하지 않았다.
