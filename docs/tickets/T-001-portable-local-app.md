# T-001: Rust·Nuxt 휴대 실행 검증과 첫 저장 흐름

- 상태: 준비 — 구현 미착수, 앱 구현은 후속 사용자 요청 시 시작
- 작성일: 2026-10-24
- 관련: D-10~D-13, C-01, D-05, [ADR-005](../decisions/ADR-005-rust-nuxt-local-server.md)

## 목표와 범위

Rust 서버에 Nuxt 정적 UI를 내장한 OS별 바이너리의 실행·종료·데이터 보존을 먼저 검증한다. 첫 업무 흐름은 가상 재료의 이름·관리 단위 등록 → 저장 → 목록·상세 조회로 좁히는 안을 제안한다. 재고·원가 전 기능, Electron·자동 업데이트·서버 배포·초기 자료 이관은 포함하지 않는다.

## 착수 전 설계

- 권장 라이브러리·도구 버전, 지원 OS·아키텍처·브라우저 검증 목록과 빌드 순서를 정한다.
- 품목 ID·관리 단위와 스키마 버전, 변경 기록의 JSON 형식·버전, 저장 완료 의미·실패 복구를 정한다. 수량·원가를 추가하는 티켓에서는 단위·정밀도 및 O-01~O-04 알고리즘을 선행 설계한다.
- heartbeat의 초기 대기·Ping/Pong·복수 연결·재연결·절전 복귀·안전 종료 상태를 정한다. ADR의 시간값은 검증용 제안이다.
- 사진을 포함한 전체 복원·OS 간 이동과 과거 DB·JSON 호환은 별도 설계/검증 묶음으로 연결한다. T-001의 작은 저장 흐름만으로 전체 복원을 완료 처리하지 않는다.

## 구현 메모

Nuxt는 정적 SPA 생성, Rust는 HTTP·WebSocket·DB·파일 저장을 담당하는 안이다. OS별 빌드는 각각 해당 OS 환경에서 먼저 검증한다. `cargo build --release` 전에 UI를 생성해야 하며, 빌드 자동화는 아직 없다. 브라우저 연결 정책과 업무 처리를 분리해 향후 서버 모드에서도 업무 코드를 사용할 수 있게 한다.

## 검증 결과

- 문서 준비만 수행했다. 앱 매니페스트·실행 명령은 아직 없으므로 빌드·테스트·수동 실행은 **미검증**이다.
- 구현 시 실제로 만든 명령을 README와 이 티켓에 추가한다. 위 수용 시나리오별 OS·브라우저·성공/실패·미검증 사유를 기록한다.
- 후속: 품목/전환 모델, 수량·금액 정밀도, 원가·정정·지연 입고 보정, JSON 재생과 사진을 포함한 전체 복원, 이전 정식 버전별 회귀 fixture.
