# T-032: 시트형 화면에서 직접 일괄 입력

- 상태: 완료 — 일괄 입력·외부 초안 후속 회복 검증 완료
- 단계: 이번 재개의 추가 실행 범위
- 작성일: 2026-10-25
- 관련 요구: D-01·D-05·D-08·D-09
- 선행: [T-003](T-003-materials-and-units.md), [T-004](T-004-recipes-and-costs.md), [T-005](T-005-business-history.md), [T-007](T-007-receipts.md)
- 기준: [요구사항](../REQUIREMENTS.md), [백로그 등록 결정](../decisions/ADR-008-bulk-entry-backlog.md)

## 목적

파일 준비 없이 앱의 시트형 화면에서 재료·메뉴·입고 정보를 한꺼번에 입력한다.

## 포함 범위

행·열로 된 화면에서 재료·메뉴·입고 정보를 직접 여러 건 입력·수정하고, 등록할 내용을 확인한 뒤 일괄 등록한다. 입고에는 재료·실제 수량·단위·구입금액·입고일을 포함한다.

## 제외 범위

파일 양식 다운로드·업로드(T-031), CSV 업로드 결과 편집(T-033), 범용 스프레드시트의 수식·서식 편집 기능. 기존 T-014의 판매·생산·폐기·실사 작업 화면 범위를 변경하지 않는다.

## 수용 기준

- [x] T-032-01: 파일 없이 시트형 화면에서 여러 행의 재료·메뉴·입고 정보를 직접 입력·수정할 수 있다.
- [x] T-032-02: 등록할 내용과 입력 오류를 확인하고 등록 버튼으로 일괄 확정하며 결과를 조회한다. 편집 중인 입력을 실제 입고나 확정 데이터로 반영하지 않는다.
- [x] T-032-03: 기존 ID·단위·빈 값/0원·입고일/입력 시각·버전·JSON 기록·재시도 정책을 유지한다. 실사에 포함된 지연 입고는 T-007·T-011의 중복 방지 정책을 따른다.
- [x] T-032-04: 열 구성·참조 선택·중복 및 오류 행의 전체/일부 등록 정책과 키보드 입력 흐름을 착수 때 구체화한다.

## 검증 방법

가상 재료·메뉴·입고 자료로 여러 행 입력→수정→확인→등록→조회, 오류 수정·취소·빈 값/0원·재시도를 검증한다. 구현 시 [공통 완료 조건](README.md#공통-완료-조건)의 해당 검증을 수행한다.

## 채택한 기술 선택

열·참조·행 추가/삭제·탭 구분 붙여넣기·키보드·탭 보관은 ADR-010의 공통 표로 구체화했다. 전체 사전검사와 항목별 등록·부분 성공 정지/재검토·원요청 재시도를 사용한다. T-031/T-033과 검증·실행기를 공유한다.

## 검증 결과

[공통 검증 기록](../refs/T-031-T-033-verification.md)에 수용 기준별 실제 결과·변경 파일·최초 실패/수정·최종 실행과 세 티켓 각각의 After13을 기록했다. UI165·입고 HTTP12(신규4 포함)·최종 bulk 브라우저13·6화면/키보드/3종 양식을 확인했다. [공통 Before4/계획](T-031-T-033-plan.md)과 [ADR-010](../decisions/ADR-010-unified-bulk-entry.md)의 채택 기술 계약을 따른다. T-021의 전체 회귀/성능·필수 외부 조건은 이 티켓의 완료와 구분한다.

후속 검토에서 미완성 외부 입고 초안의 재열기와 발주 연결 초안의 안내 누락을 재현·보완했다. 닫힌 편집 형식과 원본문·기존 초안 링크를 유지하며 표준 최종 빌드 뒤 bulk13·단위165·타입/정적 검사를 확인했다. 최초 실행·관측 수정·후속 결과와 고유 시험 범위는 공통 검증 기록에서 구분한다.
