# T-001 구현·검증 계획

- 일자: 2026-10-24
- 명세: [T-001](T-001-portable-local-app.md), [ADR-005](../decisions/ADR-005-rust-nuxt-local-server.md)
- 범위: 로컬 실행 기반과 재료 이름·관리 단위 등록/목록/상세. 후속 TODO를 새 구현 티켓으로 취급하지 않는다.

## 구현 선택

Nuxt 정적 SPA를 Rust 바이너리에 내장한다. Node 서버를 함께 배포하는 대안은 단일 바이너리 조건에 맞지 않아 채택하지 않는다. Axum/Tokio는 HTTP·WebSocket, rusqlite bundled는 SQLite를 담당한다. 구체 버전은 잠금 파일과 실행 결과에 기록한다.

SQLite와 JSON 파일을 동시에 원자적으로 갱신할 수 없으므로, 재료와 전체 상태 JSON 본문을 SQLite의 한 트랜잭션에 저장한 뒤 불변 JSON 파일로 내보낸다. 파일 발행 실패는 저장 완료로 응답하지 않는다. 재시작·같은 요청 ID 재시도 때 복구하며 중복 재료를 생성하지 않는다. 전체 복원·사진 처리는 이번 범위 밖이다.

## 작업 단위와 계약

1. **저장 계층** — `src/store.rs`, `tests/storage.rs`, 합성 SQL fixture. `Store::open(&Path)`, `list`, `get`, `create(CreateMaterial)`를 제공한다. `Material`은 UUID ID·이름·관리 단위·UTC 생성 시각이다. 요청 ID는 UUID로 재시도와 중복 저장을 구분한다. 이름은 trim 후 1~100자, 단위는 1~20자이며 제어 문자는 거절한다. 단위 환산과 수량은 다루지 않는다.
2. **실행·서버** — `src/lifecycle.rs`, `src/server.rs`, `src/main.rs`, `tests/http.rs`. 실행파일 옆 db/, 단일 작성자 잠금, loopback 임의 포트, 브라우저 자동 열기, Host·Origin·세션 검증. GET/POST `/api/materials`, GET `/api/materials/{id}`, POST `/api/session`, WS `/api/heartbeat`. 오류는 HTTP 오류 코드와 JSON으로 반환한다.
3. **UI·빌드** — `frontend/`, `scripts/`, `build.rs`. 한국어 등록·목록·상세, 정확히 같은 요청의 재시도, 연결 상실 안내. Nuxt generate → 입력/산출물 해시 확인 → Cargo release 순서. 소스 변경·자산 누락·변조를 검출한다.
4. **통합 검증·문서** — 실제 release와 브라우저로 등록·조회·새로고침·재시작·복수 탭을 검증한다. README·구조·티켓·TODO·연결 노트에 결과를 반영한다. 검증된 논리 단위별로 공개 경로만 커밋한다.

## 주요 검증

- [x] 저장: 입력 검증, 재실행 보존, 같은 요청 재시도·충돌, 파일 실패·복구·변조, 중복 프로세스 잠금.
- [x] 호환: 합성 과거 스키마 보존, 마이그레이션 실패 원본 유지, 미래 스키마 쓰기 거절.
- [x] 수명: 초기 대기 120초, Ping 15초/Pong 만료 45초, 연결 0개 유예 120초. 복수 탭·재연결·관측 시간 공백·진행 중 저장 종료를 실제 코드로 검증.
- [x] 보안/라우팅: 외부 Host·Origin·세션 없는 요청 거절, API/자산 404가 HTML 200으로 바뀌지 않음, 상세 직접 진입.
- [x] 빌드: 생성 자산 누락·오래된 입력·산출물 변조 실패, release 자산 내장, 시스템 의존성 검사.
- [x] UI: 가상 재료 저장·상세·새로고침·중복 입력·오류 보존, PC/좁은 화면·다크 모드.
- [ ] 휴대 실행: macOS의 한글·공백 경로/다른 CWD/중복 실행/잘못된 db 경로/정상 종료 후 같은 OS 이동 확인. OS별 권한·별도 PC·OS 간 이동은 미검증.

자동 시간 테스트는 실제 OS 절전을 대신하지 않는다. 개발 도구 없는 별도 Windows/Mac, 브라우저 강제 종료, 실제 절전 복귀, OS 간 이동을 실행하지 못하면 미검증으로 남기고 T-001을 완료 처리하지 않는다.

## 변경 전 검토

[Step 1] 변경 계획 - PASS: 위 범위·계약·테스트와 기존 티켓의 수용 기준을 연결했다.

[Step 2] 계획 검토 - PASS: 기존 변경 없음. 운영 db/·빌드 산출물을 실행 전에 제외한다. 공개 자료는 가상 데이터만 사용한다.

[Step 3] 검토 재검토 - PASS: 현재 macOS ARM64의 성공이 다른 OS·절전·배포 성공을 뜻하지 않는다. JSON 실패는 재시도가 필요한 상태로 취급한다.

[Step 4] 계획 단순화 - PASS: 수량·원가·사진·복원을 추가하지 않는다. 바이너리 교체를 통한 이전 DB 지원 방향을 유지한다.

되돌릴 때는 앱을 종료하고 db/ 전체를 먼저 보존한다. 공개 코드 커밋은 논리 단위로 되돌릴 수 있으나 새 스키마를 이전 앱으로 여는 것은 보장하지 않는다.
