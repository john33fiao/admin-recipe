## 목적

개별 기능 성공을 실제 업무 전체의 수량·가치·기록 일관성으로 확인한다.

## 포함 범위

가상 전체 운영 시나리오, 저장/복원 장애·호환·UI·공개 자료 경계와 OS별 잔여 검증을 대조하고 결과를 기록한다.

## 제외 범위

실제 운영 자료의 공개·전체 이관, 승인 없는 배포/게시·T-001 미검증 자동 완료. 별도 승인된 비공개 자료 시연은 격리 환경에서 수행하고 공개 산출물과 분리한다.

## 검증 방법

T-017·T-019 완료 후 README의 build·Rust fmt/test/clippy·UI test/typecheck/e2e·manifest/release 검사로 T-021-01~04의 통합 검증을 수행하고 T-021-06에 결과와 한계를 기록한다. T-001의 실환경 검증이 남아 있어도 실행 가능한 검증은 진행한다. 별도 장비 등 필요한 환경을 확보하면 T-021-05의 실환경 시나리오를 검증한다. 환경이 없으면 해당 기준을 미검증으로 유지하고 티켓 최종 완료·배포 준비 완료로 처리하지 않는다.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[초기 통합·지정 시연과 최종 검증 기록](../refs/T-021-integration-verification.md)을 따른다. macOS arm64의 실제 release·Chromium에서 가상 전체 연결48개와 지정 비공개 시연90개를 확인했다. 일괄 입력 이후 최종 후보에서 가상48개를 재실행하고 같은 시연 DB의 보존된 복사본 읽기10개를 확인했다. 최초 시험 관측 오류와 후속 실행은 구분하며 서로 겹치는 단언을 합산하지 않는다. 지정 자료 검증기3개 통과는 실제 앱 시연과 별도 근거다. 기본120초 자연종료·재시작과 같은 시연 DB의5행/메뉴 화면 읽기를 확인했다. 최종 영향 확인은 재고를 새로 적재하지 않았고 원시연 전체 파일은 바이트가 동일하다.

전체 Rust는 실제66개 묶음 합계631 PASS·종료0이다. 기존 브라우저122개 실행은119 PASS·3 FAIL이었고, 관측 보완 뒤 이전 실패3개만 별도 후보에서3 PASS였다. 고유 시나리오 집합122개와 서로 다른 후보·실행을 구분하며 단일 바이너리122개 일괄 통과로 표현하지 않는다. 일괄 입력의 새13개·UI165개·입고 HTTP12개와 전체 통합48개도 각각의 범위로 기록한다.

[보안 검토](../refs/T-021-security-review.md)의 의존성 잔여 항목을 유지한다. 최종 release의 판매·재료 규모별 성능은1회 PASS·종료0,146.569초다. 저장·시작과 읽기/화면을 나눠 측정했으며 누적 JSON 전체 검사 경로의 비용을 확인했다. 100판매 배분 후 JSON128.128MB와 별도 재료100개 JSON14.753MB를 포함한 전체 기록을 보존했다. 단일 개발 장비 관측이며 과거 debug 시간과 엄밀한 배율·운영 보장을 만들지 않는다.

T-001의 별도 깨끗한 Windows/Mac·실제 절전·지원 환경·다운로드 실행/서명은 미검증이다. 해당 조건 없이 T-021·배포 준비·전체 goal을 완료 처리하지 않는다.

### 선행 티켓의 누적 비용 관측

T-010에서 가상 판매101건을 정상 Store 초안/확정으로 누적한 뒤 실사 배분을 검증했다. `cargo test --locked --no-fail-fast`의 `stocktake_storage` 14개는 모두 통과했지만 Windows x64의 debug 실행에서629.75초가 걸렸고 대부분은101건 누적 사례였다. 변경마다 기존 전체 JSON을 재검증하는 현재 저장 경로의 비용이 포함된다. 이는 release 성능이나 개별 저장 지연을 분리 측정한 결과가 아니다. T-021-03에서 release·자료 규모별 저장/시작 검사 시간과 JSON 누적 크기를 측정하고 보존·무결성 조건을 유지하는 개선을 검토한다.

T-012의 전체 Rust 회귀443건도 통과했으며 같은 `stocktake_storage`14건은682.86초였다. 정정 원본/유효 이력과 커밋 전 의미 검증이 추가된 상태의 debug 근거로 보존한다. 이 수치만으로 release 성능이나 배포 준비를 판정하지 않는다.

T-018의101건 누적 실사를 포함한 `stocktake_storage` debug 시험 묶음은2446.14초였다. 당시 다른 빌드·검증도 동시에 실행되어 이 값과 이전629.75초·682.86초는 자료 규모별 release 측정의 비교 기준이 아니다. 엄밀한 성능 배율이나 개별 release 저장 지연으로 해석하지 않는다. 현재 최종 release에서는 다른 빌드·시험을 마친 뒤 저장·시작·조회와 JSON 크기를 별도로 측정한다.
