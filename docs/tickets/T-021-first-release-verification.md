- 상태: 대기 — T-017·T-019 완료 후 통합 검증 착수, 실환경 검증은 별도 완료 조건
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-01~C-03, D-01~D-05·D-08~D-13
- 선행: [T-017](T-017-operations-overview.md), [T-019](T-019-data-compatibility.md)
- 최종 완료 조건: 이 티켓의 모든 수용 기준과 [T-001](T-001-portable-local-app.md)의 필수 잔여 검증 충족. T-001의 미완료는 통합 검증 착수를 막지 않는다.
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

개별 기능 성공을 실제 업무 전체의 수량·가치·기록 일관성으로 확인한다.

## 포함 범위

가상 전체 운영 시나리오, 저장/복원 장애·호환·UI·공개 자료 경계와 OS별 잔여 검증을 대조하고 결과를 기록한다.

## 제외 범위

실제 운영 자료·승인 없는 배포/게시·T-001 미검증 자동 완료.

## 수용 기준

- [ ] T-021-01: 사전 가격→발주/직접 입고→손질/비축→판매→명시 폐기→실사/배분→정정→반품→복원 흐름의 수량·가치를 대조한다.
- [ ] T-021-02: 판매 자체의 재고 불변, 판매 개수 비례 배분, 0원·0 수량 허용, 미래 판매만 레시피 변경, 현재 평균 단가 반품을 회귀 시나리오로 고정한다.
- [ ] T-021-03: 가상 누적 데이터로 목록·검색·그래프·JSON 크기/시작 검사 시간을 측정하고 환경·자료 규모·한계를 기록한다. 무기한 보관을 임의 삭제로 해결하지 않는다.
- [ ] T-021-04: 세션/Origin·파일/사진·복원 입력·의존성·공개 산출물을 변화 범위에 맞춰 검토한다. 기존 보안 검토의 잔여 권고도 재확인한다.
- [ ] T-021-05: T-001의 개발 도구 없는 별도 장비·실제 절전·지원 OS/브라우저·다운로드 실행/서명 검증을 실제 증거로 판정한다. 환경이 없으면 해당 항목 미검증으로 남기고 배포 준비 완료로 보고하지 않는다.
- [ ] T-021-06: 테스트 명령·결과·도구/OS·미검증, README/요구사항/티켓 상태를 일치시킨다. OS 왕복은 백로그라는 결정은 유지한다.

## 검증 방법

T-017·T-019 완료 후 README의 build·Rust fmt/test/clippy·UI test/typecheck/e2e·manifest/release 검사로 T-021-01~04의 통합 검증을 수행하고 T-021-06에 결과와 한계를 기록한다. T-001의 실환경 검증이 남아 있어도 실행 가능한 검증은 진행한다. 별도 장비 등 필요한 환경을 확보하면 T-021-05의 실환경 시나리오를 검증한다. 환경이 없으면 해당 기준을 미검증으로 유지하고 티켓 최종 완료·배포 준비 완료로 처리하지 않는다. 현재 문서 보완 단계에서는 앱 검증을 실행하지 않는다.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.

### 선행 티켓의 누적 비용 관측

T-010에서 가상 판매101건을 정상 Store 초안/확정으로 누적한 뒤 실사 배분을 검증했다. `cargo test --locked --no-fail-fast`의 `stocktake_storage` 14개는 모두 통과했지만 Windows x64의 debug 실행에서629.75초가 걸렸고 대부분은101건 누적 사례였다. 변경마다 기존 전체 JSON을 재검증하는 현재 저장 경로의 비용이 포함된다. 이는 release 성능이나 개별 저장 지연을 분리 측정한 결과가 아니다. T-021-03에서 release·자료 규모별 저장/시작 검사 시간과 JSON 누적 크기를 측정하고 보존·무결성 조건을 유지하는 개선을 검토한다.

T-012의 전체 Rust 회귀443건도 통과했으며 같은 `stocktake_storage`14건은682.86초였다. 정정 원본/유효 이력과 커밋 전 의미 검증이 추가된 상태의 debug 근거로 보존한다. 이 수치만으로 release 성능이나 배포 준비를 판정하지 않는다.
