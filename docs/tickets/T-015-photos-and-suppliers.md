# T-015: 사진·대표 사진·설명과 구입처

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-09·D-11·D-13, P-12
- 선행: [T-004](T-004-recipes-and-costs.md), [T-005](T-005-business-history.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

재료와 메뉴를 사진·설명으로 확인하고 구입처를 바로 찾는다.

## 포함 범위

재료·메뉴의 여러 사진·대표 사진 지정, 설명·구입처 링크/설명 여러 건을 등록·수정·조회한다.

## 제외 범위

외부 사진 호스팅·이미지 생성·거래처 발주 전송.

## 수용 기준

- [ ] T-015-01: 사진 여러 장 중 대표 1장을 지정한다. 사진이 없는 경우도 정상 등록하며 링크 또는 설명만으로 구입처를 저장할 수 있다.
- [ ] T-015-02: 사진을 고유명칭으로 db/ 안에 보관하고 원본 기기 절대경로에 의존하지 않는다.
- [ ] T-015-03: 사진 교체·제거 뒤에도 과거 버전/복원 지점이 참조하는 자산은 보존한다. 제거는 현재 연결 해제와 구분한다.
- [ ] T-015-04: 파일 종류·용량·깨진 이미지·위험한 파일명·경로 이탈을 검증하고 실패 시 기존 연결을 유지한다. 실제 허용 형식/상한은 구현 설계에 기록한다.
- [ ] T-015-05: 사용자 링크/설명을 안전하게 표시하고 위험한 URL 스킴을 실행하지 않는다. 로컬 파일 경로를 웹 정적 자산으로 노출하지 않는다.
- [ ] T-015-06: DB·JSON·사진 연결의 완료/실패/재시도와 메뉴 복제 시 자산 공유·참조 보존을 검증한다.

## 검증 방법

가상 사진의 등록/대표 변경/교체/아카이브·악성 파일명/URL·실패·같은 OS 경로 이동·과거 참조 저장/API/UI 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
