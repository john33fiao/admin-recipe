# T-031: Excel·CSV 양식 업로드와 확인 후 일괄 등록

- 상태: 완료 — CSV/공통 편집표 구현·관련 수용 검증 완료
- 단계: 이번 재개의 추가 실행 범위
- 작성일: 2026-10-25
- 관련 요구: D-01·D-05·D-08·D-09, C-05
- 선행: [T-003](T-003-materials-and-units.md), [T-004](T-004-recipes-and-costs.md), [T-005](T-005-business-history.md), [T-007](T-007-receipts.md)
- 기준: [요구사항](../REQUIREMENTS.md), [백로그 등록 결정](../decisions/ADR-008-bulk-entry-backlog.md)

## 목적

예제 양식을 내려받아 재료·메뉴와 입고 정보를 여러 건 작성하고, 등록될 내용을 확인한 뒤 한 번에 등록한다.

## 포함 범위

Excel 또는 CSV 예제 양식 다운로드 → 파일에 정보 입력 → 업로드 → DB에 추가할 내용·형식 미리보기 → 사용자가 등록 버튼을 눌러 일괄 등록하는 흐름이다. 입고에도 적용하며 재료·실제 수량·단위·구입금액·입고일을 다룬다. 예제는 가상 데이터로 작성한다.

## 제외 범위

특정 과거 운영 자료의 정제·초기 이관, 앱 검증을 거치지 않는 직접 DB 주입. 시트 직접 입력은 [T-032](T-032-sheet-bulk-entry.md), 업로드 확인 화면의 직접 편집 통합안은 [T-033](T-033-editable-import-preview.md)에 둔다.

## 수용 기준

- [x] T-031-01: 재료·메뉴·입고용 예제 양식을 내려받고 작성 방법을 확인할 수 있다. 정확한 파일 형식·열 구성은 착수 때 정한다.
- [x] T-031-02: 업로드 후 어떤 항목·값·참조로 DB에 추가되는지 확인 화면에서 보여주고, 등록 버튼을 누르기 전에는 업무를 확정하지 않는다.
- [x] T-031-03: 입고 수량·단위·구입금액·입고일을 일괄 입력하며 빈 값/0원과 입고일/입력 시각을 구분한다. 지연 입고는 T-007·T-011의 실사 포함량 확인·중복 방지 정책을 따른다.
- [x] T-031-04: 등록 버튼으로 확인한 내용을 반영하고 결과를 조회한다. 기존 ID·단위·버전·JSON 기록·재시도 정책을 유지하며 재료·가격 등록을 실제 입고로 취급하지 않는다.
- [x] T-031-05: 잘못된 형식·참조·단위, 중복·재업로드와 오류 행의 전체/일부 등록 정책을 정하고 사용자에게 처리 결과를 알린다.

## 검증 방법

가상 재료·메뉴·입고 파일로 양식 다운로드→작성→업로드→미리보기→등록→조회 흐름을 확인한다. 취소·오류·0원/빈 값·같은 요청 재시도·실사에 포함된 지연 입고를 함께 검증한다. 구현 시 [공통 완료 조건](README.md#공통-완료-조건)의 해당 검증을 수행한다.

## 채택한 기술 선택

형식·열·통합·제한·중복/부분 성공은 ADR-010에서 구체화했다. UTF-8 CSV와 공통 편집표를 사용하며 파일/붙여넣기1MiB·200행, 메뉴 묶음/직접 참조, 전체 사전검사 뒤 항목별 정상 API 등록을 적용한다. xlsx 지원·전체 운영 자료 이관은 이번 범위에 넣지 않는다.

## 검증 결과

[공통 검증 기록](../refs/T-031-T-033-verification.md)에 수용 기준별 실제 결과·변경 파일·최초 실패/수정·최종 실행과 세 티켓 각각의 After13을 기록했다. UI164·최종 입고 HTTP12(신규4 포함)·bulk 브라우저11·6화면/키보드/3종 양식을 확인했다. [공통 Before4/계획](T-031-T-033-plan.md)과 [ADR-010](../decisions/ADR-010-unified-bulk-entry.md)의 채택 기술 계약을 따른다. T-021의 전체 회귀/성능·필수 외부 조건은 이 티켓의 완료와 구분한다.
