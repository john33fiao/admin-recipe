# T-006: 발주 내역과 미입고 주문량

- 상태: 완료 — 발주·순수 종료 계약 검증, 실제 입고 연결은 T-007
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-01·D-05·D-08, P-05·P-06
- 선행: [T-003](T-003-materials-and-units.md), [T-005](T-005-business-history.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

주문한 수량과 현재 보유량을 분리해 입고 예정 상태를 파악한다.

## 포함 범위

재료별 실제 수량 단위의 주문 작성·조회·수정 이력·미입고 취소와 입고 종료 연결을 구현한다.

## 제외 범위

발주서 출력·외부 전송·부분 입고·거래처 마스터/결제 관리.

## 수용 기준

- [x] T-006-01: kg·L 등 호환 단위 주문량을 직접 입력하고 거래처명·예정일·예상 금액은 선택 입력한다.
- [x] T-006-02: 발주 저장만으로 보유 재고·가치를 바꾸지 않는다. 미입고량을 판매 가능한 현재고에 더하지 않는다.
- [x] T-006-03: 미입고 취소는 주문 상태만 바꾸며 없는 재고·원가를 차감하지 않는다.
- [x] T-006-04: 입고 1회로 종료하는 상태 전이·원 주문량/실입고량/차이의 저장 계약을 정의하고 가상 입고 결과로 검증한다. 실제 입고 UI와 연결은 T-007에서 완성한다. 10kg 주문→9.8kg 입고 뒤 0.2kg을 미입고로 남기지 않는 계약이다.
- [x] T-006-05: 입고·취소 뒤 중복 확정 및 잘못된 상태 전환을 방지하고 원기록과 이력을 조회한다. 취소는 실제 저장/API/UI, 입고 뒤 상태는 순수 종료 계약으로 검증했으며 실제 입고 저장 회귀는 T-007에서 확인한다.

## 검증 방법

주문→취소·주문→입고 종료·수량 차이·재시도와 재고 불변 저장/API/UI 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[구현 계획과 RTD Before](T-006-plan.md)에 따라 주문 초안·확정·수정·취소와 schema5를 구현했다. [검증 기록](T-006-verification.md)에 기준별 근거·실제 RED와 GREEN·RTD After를 기록했다. Windows에서 Rust99·UI 단위22·타입/포맷/정적 검사·정식 빌드·브라우저29개를 통과했다. 기본120초 정상 종료 후 DB 초안 복구, 응답 유실 재시도·다른 탭 충돌·이력과 이전 JSON 보존을 확인했다. 6개 반응형/테마 화면과 키보드 입력·저장·미리보기·확정을 확인했다.

다음은 T-007 실제 입고·보유 원가와 주문 종료의 같은 트랜잭션 연결이다. T-006의 순수 가상 입고 종료를 실제 입고 UI/API 성공으로 해석하지 않는다. 별도 깨끗한 Windows/Mac·실제 절전과 T-021 시연은 미완료다.
