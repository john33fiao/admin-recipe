# T-006: 발주 내역과 미입고 주문량

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-01·D-05·D-08, P-05·P-06
- 선행: [T-003](T-003-materials-and-units.md), [T-005](T-005-business-history.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

주문한 수량과 현재 보유량을 분리해 입고 예정 상태를 파악한다.

## 포함 범위

재료별 실제 수량 단위의 주문 작성·조회·수정 이력·미입고 취소와 입고 종료 연결을 구현한다.

## 제외 범위

발주서 출력·외부 전송·부분 입고·거래처 마스터/결제 관리.

## 수용 기준

- [ ] T-006-01: kg·L 등 호환 단위 주문량을 직접 입력하고 거래처명·예정일·예상 금액은 선택 입력한다.
- [ ] T-006-02: 발주 저장만으로 보유 재고·가치를 바꾸지 않는다. 미입고량을 판매 가능한 현재고에 더하지 않는다.
- [ ] T-006-03: 미입고 취소는 주문 상태만 바꾸며 없는 재고·원가를 차감하지 않는다.
- [ ] T-006-04: 입고 1회로 종료하는 상태 전이·원 주문량/실입고량/차이의 저장 계약을 정의하고 가상 입고 결과로 검증한다. 실제 입고 UI와 연결은 T-007에서 완성한다. 10kg 주문→9.8kg 입고 뒤 0.2kg을 미입고로 남기지 않는 계약이다.
- [ ] T-006-05: 입고·취소 뒤 중복 확정 및 잘못된 상태 전환을 방지하고 원기록과 이력을 조회한다.

## 검증 방법

주문→취소·주문→입고 종료·수량 차이·재시도와 재고 불변 저장/API/UI 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
