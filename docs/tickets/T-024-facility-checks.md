# T-024: 시설 점검 카테고리·항목·일일 기록

- 상태: 백로그 — 구체화/착수 대기
- 단계: 백로그
- 작성일: 2026-10-24
- 관련 요구: D-07
- 선행: 없음
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

시설 운영 점검 항목을 직접 설정하고 일일 수행 이력을 남긴다.

## 포함 범위

관리페이지의 카테고리→하위 항목 편집과 일일 완료 기록을 후속 기능으로 보존한다.

## 제외 범위

1차·2차 자동 포함·초기 네트워크 접속 확대.

## 수용 기준

- [ ] T-024-01: 카테고리·항목을 고정 목록 대신 편집하며 일일 수행 기록과 점검표 정의를 구분한다.
- [ ] T-024-02: 점검표 변경·아카이빙 후에도 과거 항목명/결과를 보존한다.
- [ ] T-024-03: 수행 여부와 이상/조치 완료·휴무/해당 없음 등의 필요성을 착수 시 확인한다.
- [ ] T-024-04: 수치·사진·알림·수리/주간/월간 점검과 기기 공유 여부를 별도 결정한 뒤 구현 하위 작업을 만든다.

## 검증 방법

점검표 변경 전후 과거 기록 유지와 날짜별 새 기록 사례로 요구 검토. 현재 구현/실행 검증 없음.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

백로그 우선순위 승인 및 점검 입력/주기/연계 범위 확정

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
