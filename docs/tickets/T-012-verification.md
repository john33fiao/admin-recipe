## 첫 통합 실행의 실패와 수정

첫 `node scripts/build.mjs`는 UI 생성 후 Rust 연결의 타입/인자 오류2건으로 종료101이었다. 두 연결을 수정한 두 번째 표준 빌드는 종료0이며 release의 개인 홈/프로젝트 경로 잔존 검사도 통과했다. 현재 UI manifest 검사도 종료0이다.

첫 관련 Cargo 실행은 큰 시험 입력 매크로의 재귀 한도 때문에 컴파일 단계에서 종료101이었다. 시험 crate에만 한도를256으로 지정한 다음 실행은104건 중98건 성공·6건 실패였다. 내부 단위/자료 읽기38건, HTTP6건, 기존 포함 출처16건과 가치14건은 모두 성공했다. 실패는 순수 계산1건, 정정 후 일반 업무1건, 저장4건이었다.

금액 상한 실패는 출처 수량을 계산하는 중간 단계가 보정 전 가치까지 계산한 원인이었다. 이 단계의 수량/출처 계산과 마지막 실제 가치 검증을 분리한 뒤 `cargo test --locked --test correction`은13/13·종료0이다. 저장 실패 중 부분 폐기의 가치 기대90은 기존 총가치 보존 정책과 달라, 시험을 수량9·가치100 확인으로 바로잡았다. 제품의 폐기 계산은 변경하지 않았다.

관측/판매 배분 실패는 과거 입력 revision으로 조회할 때 실제로는 나중에 저장한 새 소모 개정이 포함된 원인이었다. 원행의 관측 시점과 파생행의 실제 기록 시점을 구분했다. 포함 입고로 전환한 뒤의 새 일반 입고, 정정된 관측 뒤의 생산·폐기가 현재 유효 근거를 조회하도록 연결했다. 실제 원기록 검증에서는 보존한 원관측을 사용하고 현재 결과 검증에서는 유효 관측을 사용한다.

신규 Chromium7건의 첫 실행은4건 성공·3건 실패였다. 실패3건은 모두 확정 API의503이며, 입력/원요청은 화면에 보존됐다. DB 커밋 후에 발견되던 의미 검증 실패를 트랜잭션 안에서 먼저 검사하도록 보강하고 SQL 오류와 구분한 롤백 시험을 추가했다. 성공하지 않은 확정 결과를 링크 대기나 시험 기대 변경으로 통과시키지 않았다. 미리보기1440/768/390×두 테마6장은 직접 열어 잘림·겹침·가로 넘침이 없음을 확인했다. 새 가치 근거 표시 분기의 별도 화면과 키보드는 아직 검증 전이다.

## 핵심 검증 결과와 남은 실행

`cargo test --locked --lib --test correction --test correction_followup --test correction_http --test correction_storage --test reconciliation_provenance --test reconciliation_value --no-fail-fast`의 세 번째 실행은 **109/109 성공·종료0**이다. 내부 단위38·정정 순수15·정정 후 일반 업무5·HTTP6·저장15·포함 출처16·가치14건으로 구성한다.
