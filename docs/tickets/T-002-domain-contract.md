# T-002: 수량·원가와 소모 보정 계산 계약

- 상태: 착수 가능
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-01~C-03, D-02~D-05, D-08, P-02~P-04·P-07~P-11
- 선행: 없음
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

업무별 계산이 서로 다른 재고·원가를 만들지 않도록 구현 전에 입력·출력과 보존 조건을 고정한다.

## 포함 범위

품목·관리 단위·레시피 버전·재고 변동·소모 배분의 데이터 계약과 가상 수용 사례를 설계한다. 기존 재료 UUID와 DB·JSON 호환을 유지하는 확장안을 작성한다.

## 제외 범위

제품 코드 구현, 새로운 서버·다중 사용자 구조.

## 수용 기준

- [ ] T-002-01: g↔kg·mL↔L을 같은 차원으로 환산하고 g↔mL 자동 환산을 하지 않는다. 자유 단위는 명시한 동일 단위 안에서 계산한다.
- [ ] T-002-02: 수량·금액 정밀도, 반올림 잔여 배분, 범위 초과·0 나누기·가격 없음·0원과 입력 오류를 정의한다.
- [ ] T-002-03: 보유 평균 단가, 보유량 0일 때 마지막 유효 단가, 입고 전 등록 가격의 우선순위와 출처를 정의한다. 가격 등록만으로 수량·보유 가치를 만들지 않는다.
- [ ] T-002-04: 판매 자체는 재고를 차감하지 않는다. 직전 품목 실사 수량 + 확정 입고/생산 유입 - 생산 투입/반품/명시 폐기와 이번 실사 수량의 차이로 미기록 소모를 확정한다. 별도 예상 재고를 운영하지 않는다.
- [ ] T-002-05: 실사 기간에 그 재료를 직접 참조한 메뉴의 판매 개수 비율로 소모를 배분한다. 0 수량 참조도 대상이며 비축 생산에서 소모한 하위 재료를 판매에 다시 차감하지 않는다. 대상 판매가 없으면 미배분 소모로 보존한다.
- [ ] T-002-06: 첫 실사·품목별 다른 실사 시점·입력 중 장부 변경·0원·0 잔량·동일 수량 판매·정정·지연 입고 후 재실사의 가상 수용 사례를 작성한다.
- [ ] T-002-07: 레시피 변경은 이후 판매에만 적용한다. 여러 결과물은 주 결과물 원가 100%·나머지 0%를 기본으로 수정 가능하며 합계를 보존한다. 반품은 현재 평균 단가로 가치 차감한다.
- [ ] T-002-08: 기존 DB v2·JSON v1의 확장/변환안과 원기록·버전·정정·실사별 배분의 관계를 정의한다.

## 검증 방법

가상 원장의 시작값·각 처리 후 수량/보유 가치/단가/판매 소모를 수계산하여 대조한다. T-003~T-019가 사용하는 계약과 열린 질문이 모순되지 않는지 문서 검토한다.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.
