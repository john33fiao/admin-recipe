# T-005: 업무 기록·임시 저장·확정과 JSON 기록 확장

- 상태: 완료 — 공통 기반·가격 업무와 T-009 실제 판매 조건 검증
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-02, D-02·D-11~D-13, P-02·P-08·P-11
- 선행: [T-002](T-002-domain-contract.md), [T-003](T-003-materials-and-units.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

후속 업무가 같은 확정·재시도·이력 보존 규칙으로 저장되어 중복 재고 반영을 막는다.

## 포함 범위

업무별 입력 초안과 확정 기록, 요청 중복 방지, 버전/정정 참조, SQLite·JSON 발행을 기존 저장 기반에 확장한다.

## 제외 범위

외부 큐·분산 이벤트 시스템, 기존 이력 삭제.

## 수용 기준

- [x] T-005-01: 임시 저장은 재고·보유 금액에 영향을 주지 않으며 앱 재시작 후 다시 연다.
- [x] T-005-02: 판매의 레시피 수량 0·재고 부족만으로 확정을 막지 않는다. 판매는 실사 전 재고를 차감하지 않는다. 잘못된 참조·형식·서로 다른 단위 등 계산할 수 없는 입력은 이유를 표시한다.
- [x] T-005-03: 확정 업무와 수량/금액 변동·사용 버전·입력 시각·요청 식별자가 원자적으로 연결된다.
- [x] T-005-04: 동일 요청 재전송은 같은 결과를 반환하며 다른 내용으로 재사용하면 거절한다. 서로 다른 정상 판매 입력을 중복으로 오인하지 않는다.
- [x] T-005-05: 임시 저장·수정·아카이빙·확정·보정 등 영속 데이터 변경을 JSON에 포함한다. JSON 발행 실패 후 동일 요청 재시도/재시작으로 복구한다.
- [x] T-005-06: 원기록은 보존하고 정정 연결·최신 유효 상태를 조회한다. 저장 중 안전 종료와 기존 세션/Origin 경계를 유지한다.

01·03·05·06은 공통 기반과 실제 가격 업무의 근거로 확인했다. 실제 수량/가치·배분 효과는 각 후속 업무 티켓에서 같은 경로를 검증한다. 02와 04는 T-009의 실제 판매 handler·저장·브라우저에서 0개/0구성/보유 부족 허용·재고 불변·동일 요청 재생/충돌·별개 정상 판매2건을 확인했다.

## 검증 방법

Rust 트랜잭션·요청 충돌·JSON 실패/재시도·재시작 복구 테스트와 대표 업무 초안의 임시→확정을 확인한다. 후속 업무별 공통 경로 사용 검증은 각 기능 티켓에서 추가하고 T-021에서 통합한다.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[구현 계획과 RTD Before](T-005-plan.md)에 따라 DB 초안→실제 프로세스 재시작→편집→미리보기→가격 확정→재시작→정정 연결을 일반 UI로 확인했다. 공통 트랜잭션·불변 요청 응답·format2/schema4와 이전 JSON 원문을 보존한다. [검증 기록](T-005-verification.md)에 Rust73·영향 저장10·UI단위17·브라우저24개 시나리오와 빌드/타입/정적/자산 검사, RTD After13·파일·실행 근거를 기록했다. 이후 T-007 입고·T-008 생산과 T-009 판매도 공통 경로에 연결했다. T-009에서 남아 있던 판매 기준02·04를 실제 검증해 완료했다. 각 후속 업무의 기능 검증과 T-021 통합은 별도로 수행한다.
