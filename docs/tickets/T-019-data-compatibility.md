# T-019: 이전 DB·JSON 호환과 같은 OS 데이터 이동

- 상태: 완료 — 이전 호환·현재 Mac release의 전체 이동·보존 요청·재복원 검증
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-11~D-13
- 선행: [T-018](T-018-full-state-restore.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

새 앱으로 교체하거나 폴더를 옮겨도 업무 자료와 사진을 계속 사용한다.

## 포함 범위

업무 스키마 추가에 따른 이전 버전 fixture, 마이그레이션/실패 복구·정상 종료 후 데이터 이동과 수동 앱 교체 절차를 검증한다.

## 제외 범위

자동 업데이트·OS 간 왕복 완료 주장·서버 이관.

## 수용 기준

- [x] T-019-01: 현재 T-001 DB v2·JSON v1부터 새 버전까지 자료를 보존하여 연다. 합성 fixture와 실제 출시 버전 증거를 구분한다.
- [x] T-019-02: 새 앱이 이전 DB를 열 수 있고 미래 스키마는 쓰기 없이 거절한다. 변환 실패는 원본을 보존한다.
- [x] T-019-03: 정상 종료 후 바이너리+db/를 같은 OS의 한글·공백 경로로 옮겨 데이터·사진·정정/배분 참조를 확인한다.
- [x] T-019-04: DB만 이동했을 때 기록 복구와 JSON만 가져왔을 때 구조화 상태 복원을 구분한다. 사진을 포함하려면 db/ 전체가 필요함을 안내한다.
- [x] T-019-05: 앱 교체 전 정상 종료·보존 절차, 실패 시 지원되는 복구 절차를 README에 기록한다. 오래된 바이너리로 새 DB를 여는 역호환은 보장하지 않는다.
- [x] T-019-06: OS 간 왕복 검증은 T-027에 연결하고 이 티켓의 같은 OS 성공으로 대신하지 않는다.

## 검증 방법

과거 fixture→새 앱 변환·손상/미래 버전·변환 실패·같은 OS 경로 이동·사진·정상 종료·수동 교체 통합 시나리오.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[호환·이동 검증 기록](../refs/T-019-compatibility-verification.md)에 합성 schema1~3/과거 정상 API 가상 캡처4~14의 출처, 재사용한 T-018 실제 결과와 변경 전4개·변경 후13개 검토를 기록했다. 이전 읽기 메모는 완료 근거로 사용하지 않았다.

2026-10-25 macOS27.0.1·arm64의 현재 release·Chromium156.0.8078.4에서 정상 API로 만든 복원 상태를120초 정상 종료 후 한글·공백 경로로 이동했다.59개 API 전체값·사진2장과 기존 불변 파일11개·보존 요청·실제 재복원을 대조했다. DB-only에서는 outbox7개 원문 재발행과 사진/수입 원문·직전 상태 누락의 명시 거절을 확인했다. 세 번의 자연 종료는120081/120012/120077ms·종료0이었다. 실제 release의 미래 DB·변환 실패·미래 JSON 거절3개는 원 DB bytes를 보존했고 정지 원본의 readonly 무결성/FK도 통과했다.

README에 정상 종료→전체 사본 보존→호환 실행파일 교체/이동→조회 확인→실패 시 호환 실행파일과 그 시점의 온전한 사본 사용 절차를 기록한다. 새 DB의 역방향 호환은 보장하지 않으며 Windows↔macOS 왕복은 [T-027](T-027-cross-os-data-transfer.md)에 유지한다. T-001의 별도 장비·실제 절전·지원 환경·다운로드 실행/서명과 T-021의 최종 완료는 별도다.
