# T-028: 안정화 후 서버 이관 계획

- 상태: 후속 검토 — 구체화/착수 대기
- 단계: 후속 검토
- 작성일: 2026-10-24
- 관련 요구: D-10~D-13
- 선행: [T-021](T-021-first-release-verification.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

로컬 운영 안정화 뒤 서버로 전환할 조건과 데이터 보존 방법을 마련한다.

## 포함 범위

전환 조건·환경·접속/인증/권한·기존 데이터 이관·되돌리기와 공개/운영 자료 경계를 설계한다.

## 제외 범위

현재 서버 구축·계정/매장·공동 사용 도입.

## 수용 기준

- [ ] T-028-01: 전환 필요와 안정화 기준을 확인한 뒤 호스팅 후보·비용/운영 책임·지원 규모를 비교한다.
- [ ] T-028-02: 로컬 단일 사용자 신뢰 경계를 서버 인증/권한·백업·보관 정책으로 대체할 설계를 작성한다.
- [ ] T-028-03: 기존 DB/JSON/사진·버전/정정 참조의 검증과 이관/복구 계획을 마련한다.
- [ ] T-028-04: 사용자 결정 후 구현·배포 작업을 분리하고 현재 로컬 앱에 네트워크 공유·잠금을 선제 도입하지 않는다.

## 검증 방법

착수 시 결정 문서·이관 가상 리허설·보안 검토 계획 수립. 현재 서버 구축/배포 없음.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

안정화 후 서버 전환 요청과 운영 환경·권한 범위

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
