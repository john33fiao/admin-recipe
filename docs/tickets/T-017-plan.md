# T-017 설계·변경 전 검토

2026-10-25. [티켓](T-017-operations-overview.md)의 여섯 수용 기준과 [계산 계약](../DOMAIN-CONTRACT.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)을 따른다. T-016의 조회를 바탕으로 기존 작업 시작 화면을 실제 운영 개요로 확장한다. 스키마 v14·JSON v2·writer·재고/원가 정책을 유지한다. 예상 현재고·판매 가능 수량·내일 메뉴·시설·자동 경보·전체 원자료 이관은 추가하지 않는다.

## 마지막 확인 수량과 이후 변동

품목별 마지막 **활성 관측**의 실제 수량·당시 단위·원확인 시각·stable 관측/실사와 현재 유효 버전을 제공한다. Initial도 실제 확인이며 소모0으로 만들지 않는다. 관측 없음과 확인한0을 구분한다. 마지막 관측이 취소되면 앞선 활성 관측을 찾고 전부 취소면 미확인이다. 정정 실제 시각과 원실측 시각은 별도로 표시한다.

보존 holding의 과거 baseline version을 현재 관측으로 오인하지 않는다. 실제 정정 뒤 계산 재생에 쓰는 `holding_detail.confirmed_changes`를 실측 이후 전체 변동으로 재사용하지 않는다. 원관측의 논리 순번 뒤인 현재 유효 입고·생산·반품·폐기만 선택한다. 정정 시각이 뒤여도 원사건이 실측 앞이면 새로운 후속 변동으로 더하지 않는다. 미실측 품목은 ‘수량 확인 전 등록된 확정 변동’으로 범위를 표시한다.

생산 한 건에 같은 품목의 투입/결과가 함께 있으면 한 행에서 두 방향을 보존한다. 일반 입고의 R/A와 포함입고의 실제 구입 R/A·이미 포함 I/Ai·새 유입 U/Au·품목별 dV를 구분한다. 별도 보정은 입고 전체 값임을 표시하고 여러 품목에서 합산하지 않는다. 품목당 마지막 실측에 변동을 더해 현재고를 만들거나 다른 단위/품목 수량을 합하지 않는다.

## 조회와 전체 목록

`GET /api/overview`는 query 없이 단일 `CatalogState`에서 자료를 조립한다. 전체 품목은 현재 사용/보관 순서, 이름·ID 순서이며 품목25개를 반환한다. 품목마다 후속 변동은20행, 나머지 각 목록은20행이다. 모든 목록은 정확한 `total_count`, `returned_count`, `offset`, 고정 `page_size`, `next_offset`을 제공한다. 전체 수량/금액 합계를 새로 만들지 않는다. 개별 행에 원본문·전체 이력·전체 배분 후보·원가 행·사진 bytes를 복제하지 않는다.

`GET /api/overview/list`는 닫힌 section·offset·epoch·revision을 필수로 받고 `material_changes`에만 material_id를 필수로 받는다. 다른 section의 material_id, 미지/중복/누락 query, 비정규 정수/UUID·percent/UTF-8 오류는400이다. 원 query4096바이트 초과는414다. offset은 checked 정수이며 전체 건수 이상이면 빈 페이지와 next_offset=null을 반환한다. limit·임의 정렬·기간 필터를 추가하지 않는다.

API 목록의 state가 현재와 다르면409 `stale_state`다. 서로 다른 state의 페이지를 합치지 않고 전체 요약을 새로 읽은 뒤 첫 페이지에서 다시 시작한다. 응답은 요청 scope(section/material_id)를 돌려줘 같은 state의 다른 목록 응답도 구분한다. epoch/revision은 영구 과거 조회나 캐시가 아니라 동일한 자료로 이어 보는 조건이다. 통계의10,000개 상한에 의존하지 않고 이 페이지로 전체 근거를 끝까지 볼 수 있다.

미입고·입고 완료·취소 주문 건수는 구분하고 주문량을 실물 수량에 합하지 않는다. 원입고 취소 후 주문 재개·새 입고에서는 현재 유효 closure만 종료 차이에 사용한다. ‘최근’은 기간 필터 없이 원입력 순서의 첫 페이지라는 뜻이다. 소모 미확정은 판매/직접 품목 쌍 수이며 명시0 배분과 다르다. 미배분의 판매 없음/분모0을 표시한다. DB 초안은 미리보기를 재실행하지 않고 유효성 미평가로 표시하며 브라우저 미저장/응답 미확인 요청과 구별한다.

## 기존 조회의 재사용

T-016의 원확정 참조·현재 관측·최신 배분·정정 근거·입고 기준 선택만 작은 내부 읽기 모듈로 공유한다. 기간별 report 전체를 all-time으로 호출하거나 품목마다 holding GET을 반복하지 않는다. `StatisticsOrigin` 등 실제 의미가 같은 작은 참조 타입을 재사용하며 대규모 이름 변경은 하지 않는다. 기존 통계의 동일 자료 전체 JSON을 전후 대조한다. 새 API의 내부 Store 오류는 일반 안내로 변환한다. Host·세션·Origin·HEAD·읽기 잠금 규칙을 유지한다.

## 화면과 상태

기존 `/overview`의 ‘작업 시작’ 제목과 탐색을 유지하고 마지막 확인 수량/시각과 후속 변동을 중심에 둔다. 전체 품목 count는 ‘보관 포함’ 범위를 명시한다. 주요 작업·미입고/종료 차이·최근 기록·미배분/미확정·DB 임시 저장을 서로 다른 의미의 구역으로 제공한다. 통계·모아 입력·실제 원기록/정정 상세와 기존 판매/실사/주문/입고 생성 경로를 연결한다.

`/overview/list`는 동일 행 컴포넌트를 사용하는 section별 목록이다. URL에 section·offset·필요 품목을 보존하고 진입 시 실제 조회 state를 고정한다. 새 진입/새로고침은 최신 자료라는 것을 표시한다. 페이지 이동 중409면 이전 자료를 보존하고 전체 재조회·첫 페이지로 돌아가는 동작을 제공한다. 선택/scope/state/generation이 바뀐 뒤 도착하는 응답은 버린다.

메인에서 목록으로 이동할 때만 조회 기준을 한 번 전달한다. 목록 안에서 다른 scope로 이동할 때는 기존 reader 기준을 유지하며 나중 새 진입에 사용할 전달 상태를 남기지 않는다. UI 주소의 offset은 JavaScript 안전 정수 범위를 넘으면 명시 거절해 반올림을 막는다. API의 checked usize 범위와 끝을 넘은 빈 페이지 계약은 유지한다.

조회 실패/끊김에는 이전 결과와 실제 조회 시점을 표시한다. 새 건수만 이전 행에 섞지 않으며 업무 초안/pending을 지우지 않는다. 임의24시간 위험 판정 없이 마지막 확인 시각을 보여준다. semantic heading/table/details, 지역 스크롤·명시 초점·오류 안내·완료 알림을 유지한다. 기존 색/한글 글꼴/간격·라이트/다크 토큰을 사용하고1440/768/390px에서 직접 확인한다.

[Step 3] 검토 재검토 - PASS: 주요 가정은 현재 holding의 관측 버전이 항상 최신이 아니라는 것, 계산 재생 경계가 실측 이후 목록 경계와 다르다는 것, 페이지가 같은 state/scope여야 한다는 것이다. 각각 별도 selector·원논리 순번·409/generation 검증을 적용한다.

[Step 4] 계획 단순화 - PASS: 읽기 요약과 닫힌10개 목록만 제공한다. 새 writer·캐시·원장·예상 재고·임의 경보·범용 대시보드 엔진은 추가하지 않는다. 기존 운영 결정이나 데이터 구조가 바뀌지 않아 Obsidian에 새 정책 결정을 만들지 않는다.
