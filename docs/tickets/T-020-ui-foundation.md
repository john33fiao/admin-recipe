# T-020: 공통 탐색·입력 상태·라이트/다크와 반응형 UI

- 상태: 완료 — 공통 UI 구현·회귀 검증 통과
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-09~D-10
- 선행: 없음
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

일관된 입력·탐색으로 재료 등록부터 실사까지 사용할 수 있는 화면 기반을 마련한다.

## 포함 범위

기능 요구에 맞는 탐색 구조와 공통 표/입력/저장/오류 상태, 테마와 화면 크기 대응을 설계·구현한다. 기존 화면 초안은 참고로만 사용한다.

## 제외 범위

기존 Figma 화면 수 고정·외부 디자인 게시·모바일 접속 배포.

## 수용 기준

- [x] T-020-01: 대시보드·목록·입력·상세의 이동 구조와 빈/로딩/오류/저장 중/재시도 상태를 정리한다.
- [x] T-020-02: 라이트·다크에서 읽기와 상태 구분이 가능하고 PC·태블릿·모바일 너비에서 주요 입력·표를 사용할 수 있다.
- [x] T-020-03: 긴 화면이 콘텐츠에 따라 스크롤하며 특정 FHD 높이로 고정하지 않는다. 가로 넘침으로 주요 작업이 숨지 않는다.
- [x] T-020-04: 키보드 탐색·레이블·오류 메시지·포커스 이동과 색에만 의존하지 않는 상태 표시를 검증한다.
- [x] T-020-05: 서버 연결 안내·저장 실패 재시도와 미확정 상태를 보존한다. 최종 업무 페이지는 각 기능 티켓에서 이 기준을 적용한다.
- [x] T-020-06: 반응형 디자인을 네트워크 공동 접속·모바일 서버 지원 완료로 설명하지 않는다.

## 검증 방법

가상 자료로 세 화면 너비×두 테마의 대표 목록/입력/상세 수동 및 브라우저 검증. UI 변경 뒤 표준 빌드·타입/단위 검사.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[구현 계획과 RTD Before](T-020-plan.md)에 따라 공통 탐색·시작 화면·입력 초안 보관·포커스를 구현했다. [검증 기록](T-020-verification.md)에 실제 명령·수용 기준별 결과와 RTD After 13개를 기록했다. 표준 빌드, UI 단위 5개·타입 검사, 신규 브라우저 6개·기존 브라우저 6개, Rust 37개·포맷/정적 검사, 세 너비×두 테마의 화면 18개 검증을 통과했다.

변경 파일은 `frontend/app/app.vue`·공통 CSS·등록/목록 컴포저블·초안 복구 함수·입력/시작 페이지, UI/HTTP 테스트, 서버의 `/overview` 경로와 이 티켓/계획/검증 기록·README/구조/TODO/색인이다. 저장 중 화면 이동 뒤 초안 재등장과 시작 화면 새로고침 404를 재현·수정하고 검증했다. 다음은 T-003 재료 종류·버전·사전 가격이며 T-001의 별도 장비·실제 절전과 T-021 실제 시연은 남아 있다.
