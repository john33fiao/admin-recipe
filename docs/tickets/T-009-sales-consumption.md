# T-009: 판매 수량·금액과 실사 소모 연결

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차

- 선행: [T-004](T-004-recipes-and-costs.md), [T-008](T-008-production.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

판매를 간단히 기록하고 이후 실사에서 확정한 재료 소모와 연결한다.

## 포함 범위

메뉴별 판매 개수, 당시 레시피·판매가 버전, 판매금액과 소모 확정 상태를 기록한다.

## 제외 범위

POS·고객 환불·결제·할인·세금 자동 처리.

## 수용 기준

- [ ] T-009-01: 메뉴 판매 개수와 자동 입력 시각을 저장한다. 날짜별 영업일 마감이나 판매 때 실제 재료량 입력을 요구하지 않는다.
- [ ] T-009-02: 판매 입력 자체는 재고 수량·보유 가치를 차감하지 않는다. 레시피 수량 0·재고 부족을 이유로 판매 확정을 막지 않는다.
- [ ] T-009-03: 판매가×판매 개수의 금액을 당시 가격으로 기록한다. 이후 판매가·레시피 변경은 과거 기록을 바꾸지 않는다.
- [ ] T-009-04: 당시 레시피에서 직접 참조한 재료를 보존하고 후속 T-010의 배분 입력 계약으로 제공한다. 이 티켓에서는 소모 미확정으로 저장하며 실제 실사 배분은 T-010에서 완성한다.
- [ ] T-009-05: 실사 전 소모 미확정과 실사 후 배분 소모를 구별한다. 레시피 기반 메뉴 원가와 실사 배분 원가를 같은 측정값처럼 표시하지 않는다.
- [ ] T-009-06: 오입력 정정은 원기록과 연결하며 고객 환불·결제 반환 기능은 제공하지 않는다.

## 검증 방법

0 수량·빈 재고에서도 판매 등록, 가격/레시피 변경 후 당시 버전 유지, 판매 전후 재고 불변, 실사 배분 연결·중복 재시도 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
