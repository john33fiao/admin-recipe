# T-003: 재료·상태·단위와 사전 가격 관리

- 상태: 완료 — 재료/사전 가격 구현·검증, 실제 보유 원장 연결은 T-007
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-01·C-03, D-04~D-05·D-09, P-03·P-04·P-11
- 선행: [T-002](T-002-domain-contract.md), [T-020](T-020-ui-foundation.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

입고 전에도 재료를 준비하고 계산할 수 있으며 원물·손질분·비축품을 혼동 없이 선택한다.

## 포함 범위

기존 재료 등록·조회에 종류/상태 연결, 이름 검색, 수정·아카이브, 계산용 가격 입력과 이력을 추가한다.

## 제외 범위

별칭·고급 필터, 실제 운영 자료 이관.

## 수용 기준

- [x] T-003-01: 동일 이름이어도 UUID로 구분하며 메뉴 선택에서 원물·손질분·비축품과 관리 단위를 구별할 수 있다. 품목 선택용 조회를 검증했고 실제 레시피 연결은 T-004에서 확인한다.
- [x] T-003-02: 입고 없이 가격을 등록하고 수정 이력을 조회한다. 0원은 가격 없음과 다르며 보유 수량·금액은 늘지 않는다.
- [x] T-003-03: 재고가 있으면 보유 평균, 없으면 마지막 유효 단가와 사전 가격의 계약에 따라 가격 출처를 표시한다. 순수 resolver와 사전 가격 화면 검증 완료, 실제 보유 원장 adapter는 T-007에서 검증한다.
- [x] T-003-04: 이름·설명 수정과 아카이빙은 이전 버전을 보존한다. 아카이브 항목은 신규 입력 기본 목록에서 제외하되 과거 참조를 조회한다.
- [x] T-003-05: 다른 차원 단위로의 변경은 새 품목으로 처리한다. 기존 재고·레시피·이력 참조를 재해석하지 않는다.
- [x] T-003-06: 이름 검색의 공백·빈 결과·동일 이름·아카이브 조회와 재시작 후 지속성을 확인한다.

## 검증 방법

Rust 저장/HTTP 테스트와 UI 입력·검색·수정·아카이브 브라우저 시나리오. 기존 재료 fixture의 ID·단위 보존.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.
