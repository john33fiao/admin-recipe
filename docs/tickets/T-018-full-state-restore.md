# T-018: 사진과 버전 이력을 포함한 전체 상태 복원

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-11~D-13
- 선행: [T-014](T-014-closing-workspace.md), [T-015](T-015-photos-and-suppliers.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

원하는 기록의 전체 상태로 돌아가면서 이후 기록과 자산도 보존한다.

## 포함 범위

복원 지점 목록·검증·영향 미리보기·전체 상태 복원과 실패 복구를 구현한다. DB/JSON/사진의 일관성을 검증한다.

## 제외 범위

선택 품목 병합 복원·외부 클라우드 백업·기록 자동 삭제.

## 수용 기준

- [ ] T-018-01: 선택 JSON의 재료·메뉴·업무·버전·배분·임시 기록 등 전체 구조화 상태를 복원하며 부분 병합으로 처리하지 않는다.
- [ ] T-018-02: 복원 전 현재 상태를 보존하고 복원 작업도 새 기록으로 남긴다. 기존 지점과 무기한 기록을 삭제/덮어쓰지 않는다.
- [ ] T-018-03: 선택 시점의 사진 참조가 맞고 누락·손상 자산은 사전에 탐지한다. 구조화 자료만 옮긴 경우 사진 부재를 명확히 알린다.
- [ ] T-018-04: 손상/미래 형식·잘못된 참조·경로 이탈·일관성 오류를 변경 전에 거절한다. 실패 시 원상태와 복원 자료를 보존한다.
- [ ] T-018-05: 복원 중 저장·복수 탭 요청을 조정하여 이전 화면의 재시도가 복원 후 업무를 중복 적용하지 않도록 한다.
- [ ] T-018-06: 복원 완료 뒤 재시작·재복원·새 기록 생성이 정상이며 기존 JSON 발행 복구와 충돌하지 않는다.

## 검증 방법

이전/현재 JSON·사진 교체·아카이브·정정·실사 배분 포함 합성 데이터 전체 비교, 단계별 오류 주입·재시작·중복 요청 검증.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
