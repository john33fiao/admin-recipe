# T-014: 판매·생산·폐기·실사를 모아 입력하는 작업 화면

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-02, D-02~D-03, P-08·P-09
- 선행: [T-012](T-012-corrections-and-versions.md), [T-013](T-013-purchase-returns.md), [T-020](T-020-ui-foundation.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

여러 화면을 오가며 중복 입력하지 않고 필요한 기록을 모아 확인한다.

## 포함 범위

판매·실제 손질/비축 생산·명시 폐기·선택 실사를 한 작업 화면에서 입력하고 저장 상태와 결과를 확인한다.

## 제외 범위

하루 장부 잠금·고객 환불·모든 품목 실사 강제.

## 수용 기준

- [ ] T-014-01: 날짜별 영업일 마감·재개방을 도입하지 않고 입력 시점을 자동 기록한다.
- [ ] T-014-02: 판매를 먼저 기록해도 재고를 차감하지 않으며 실사 입력 시 확정 소모·배분 결과를 보여준다.
- [ ] T-014-03: 실사 계산 전에 같은 작업의 확정 입고·생산·반품·명시 폐기를 반영한다. 중복 차감 없이 처리 순서가 명확하다.
- [ ] T-014-04: 임시 저장을 선택하면 재시작 후 이어서 입력할 수 있다. 재고 부족·레시피 수량 0으로 정상 판매 저장을 막지 않는다.
- [ ] T-014-05: 묶음/개별 저장 단위와 재시도 식별자를 UI에 일관되게 적용하며 일부 저장 실패를 전체 성공으로 표시하지 않는다.
- [ ] T-014-06: 빈 실사 칸은 미확인, 0은 확인한 잔량 0으로 표시한다. 저장 전후 요약과 원기록 상세로 이동한다.

## 검증 방법

판매→생산/폐기→선택 실사, 일부만 입력·임시 복구·통신/JSON 실패·재시도 브라우저 시나리오.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
