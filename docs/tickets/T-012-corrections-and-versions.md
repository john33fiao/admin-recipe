# T-012: 업무 오입력 정정과 버전·아카이브 이력

- 상태: 완료 — 원기록 보존 정정·취소·영향과 이력 검증
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-02~D-04, P-02·P-08·P-09·P-11
- 선행: [T-009](T-009-sales-consumption.md), [T-010](T-010-stocktake-and-waste.md), [T-011](T-011-late-receipt-reconciliation.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

잘못 입력한 업무를 정정하면서 원기록과 실사별 소모 연결을 보존한다.

## 포함 범위

입고·생산·판매·폐기·실사 오입력의 취소/정정, 영향 미리보기와 버전 조회를 구현한다. 일반 레시피 수정은 이후 판매에만 적용한다.

## 제외 범위

레시피 변경을 과거 판매에 자동/일괄 적용, 고객 환불, 버전 이력 삭제.

## 수용 기준

- [x] T-012-01: 원기록·당시 레시피/판매가/단가를 보존하고 정정 기록으로 연결한다. 영구 삭제 대신 아카이빙한다.
- [x] T-012-02: 레시피 수량 0을 나중에 5g으로 변경해도 과거 판매·확정 소모를 재계산하지 않고 이후 판매부터 적용한다.
- [x] T-012-03: 실사 이전 판매 개수 오입력을 고치면 해당 미확정 구간의 배분 기준에 반영한다. 이미 배분된 판매를 정정하면 실사로 확인한 총소모·보유 수량/가치는 유지하고 메뉴별 배분·미배분 연결만 보정한다. 변경 전후를 미리 보여준다.
- [x] T-012-04: 실사 자체의 오입력 정정은 영향을 받는 해당 재료 구간·소모·원가를 계산 계약에 따라 보정하고 이전 실사·배분 기록을 보존한다.
- [x] T-012-05: 입고/생산/폐기를 수정할 때 후속 실사·지연 입고와 중복 보정하지 않는다. 단순 판매 정정으로 실물 재고가 되돌아왔다고 처리하지 않는다.
- [x] T-012-06: 같은 정정 재시도는 한 번만 적용한다. 아카이브된 재료/메뉴의 과거 기록도 읽을 수 있다.

## 검증 방법

레시피 0→5g 이후 판매만 적용·실사 전/후 판매 개수 정정·실사 정정·지연 입고 연결·아카이브 참조·재시도 연속 통합 테스트.

[T-008](T-008-production.md)의 생산 수량 충돌 사례에서 보존한 입력과 기존 입고/생산/실사 기록의 정정을 연결한다. T-002 계산 계약에 따라 영향 미리보기·원기록 보존·생산 기록 연결을 검증하고, 후속 실사·배분과 수량/원가를 중복 보정하지 않는지 확인한다.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

[구현 계획](T-012-plan.md)에 원본/유효 개정·수량/가치 재생·포함 연결과 검증 범위를 정리했다. 변경 전 API·UI 실패를 확인한 뒤 계산·저장·조회·화면을 통합했다. Rust 전체443건·최종 영향112건, UI80건·브라우저80건 각각과 키보드/화면 검증을 통과했다. 여섯 수용 기준과 RTD After13을 확인했다. [검증 기록](T-012-verification.md)에 실패 원인·재검증·남은 항목을 구분한다. T-011의 실제 관측 정정 writer 연결도 핵심 저장 검증에 포함했다.
