# T-004: 레시피·메뉴 복제와 사전 원가 계산

- 상태: 대기 — 선행 티켓 완료 후 착수
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: C-01·C-03, D-04·D-09, P-01~P-04·P-11
- 선행: [T-003](T-003-materials-and-units.md), [T-005](T-005-business-history.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

판매 메뉴와 비축 레시피를 등록하고 입고 여부와 관계없이 구성·분량·식재료비를 검토한다.

## 포함 범위

메뉴 1개분 또는 비축 기준 생산량, 구성 재료·수량·조리 공정/시간·설명, 판매가, 원가·원가율, 검색·양방향 참조·독립 복제를 제공한다.

## 제외 범위

세금 자동 분리·결제·할인, 실제 작업시간 측정, 과거 판매 일괄 재계산.

## 수용 기준

- [ ] T-004-01: 원물·손질재료·비축품을 직접 참조하고 모든 단계를 강제하지 않는다. 순환 레시피 참조를 거절한다.
- [ ] T-004-02: 수량 기본값 0으로 등록·판매 참조가 가능하다. ‘적당량’ 메모를 보존하며 숫자 수량을 나중에 입력하면 이후 판매부터 새 버전을 적용한다.
- [ ] T-004-03: 메뉴 1개 기준 식재료비를 합산하고 비축품 원가와 그 하위 원재료 원가를 중복 합산하지 않는다.
- [ ] T-004-04: 입고 전 등록 가격·마지막 유효 단가·현재 보유 단가로 계산하고 출처를 표시한다. 가격 없음은 완전한 0원 원가처럼 숨기지 않는다.
- [ ] T-004-05: 판매가·단순 원가율을 표시한다. 판매가가 0이거나 없으면 나누지 않고 계산 불가 사유를 표시한다.
- [ ] T-004-06: 소·중·대는 별도 메뉴다. 복제 이름은 (2)부터 충돌 없는 번호를 선택하며 복제본 편집은 원본에 영향을 주지 않는다.
- [ ] T-004-07: 레시피·가격 변경은 버전으로 보존한다. 과거 판매는 당시 버전을 참조하며 일반 레시피 수정으로 과거 판매·확정 소모를 재계산하지 않는다.

## 검증 방법

가상 재료의 1개분 합산·0 수량/0원/미입력·순환 참조·독립 복제·과거 버전 유지 단위/저장/UI 테스트.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.

## 검증 결과

미실행 — 요구사항을 티켓으로 전환한 상태다. 수용 기준 체크는 실제 구현·검증 근거가 생긴 뒤 갱신한다.
