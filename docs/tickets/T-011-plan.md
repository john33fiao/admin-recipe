# T-011 구현 계획과 RTD Before

- 작성일: 2026-10-25
- 상태: 구현·검증·RTD After13 완료 — 결과와 한계는 검증 기록 참조
- 기준: [티켓](T-011-late-receipt-reconciliation.md), [계산 계약 §8](../DOMAIN-CONTRACT.md#8-지연-입고의-수량금액-보정), [요구사항](../REQUIREMENTS.md), [ADR-007](../decisions/ADR-007-consumption-and-ticket-scope.md)
- 선행: T-007 입고·T-010 실사/폐기 핵심 구현·검증 완료. T-010의 실제 반품 연결은 T-013에 남아 있으며 이번 독립 작업을 막지 않는다.

## 1. 목적·범위·선택한 접근

기존 입고 초안에서 사용자가 실사와 이미 포함된 수량을 명시적으로 선택하고, 미포함 수량과 가치 차액을 미리보기한 뒤 한 번 확정한다. 실제 입고량 R·구입금액 A와 주문 종료는 그대로 보존한다. 현재 새 수량은 U=R-I뿐이다. 이후 생산 결과물에 남은 가치 차액과 이미 소모·전량 폐기된 부분의 별도 보정을 구별한다.

현재 원재료에 차액 전체를 가산하는 방식은 생산·소모 후의 가치를 설명하지 못한다. 과거 기록의 값을 직접 고치는 방식은 원본 보존 계약에 어긋난다. 따라서 같은 확정 수량 사건에 기존 유효 보정만 적용한 Base와 새 보정을 추가한 Proposed를 재생하고 현재 가치 차이만 저장한다. 이는 위임받은 기술 설계이며 새 운영 정책의 사용자 승인으로 표현하지 않는다.

입고일로 포함량을 추정하지 않는다. 일반 정정 writer는 T-012, 반품 writer는 T-013, 통합 작업 화면은 T-014, 실제 개발 자료 시연은 T-021이다. 실물 로트·선입선출·전체 원자료 이관은 추가하지 않는다.

## 2. 입력과 출력 계약

기존 `receipt` 업무/version1과 UUID·초안·미리보기·확정 경로를 확장한다. 기존 `unreflected`, `needs_reconciliation` 태그와 pending 원문은 유지한다. 구형 미확정 포함 확인을 조용히 일반 입고나 새 확인으로 변환하지 않는다.

```text
stock_effect = { kind: "reconciled", selections: [
  { observation_version_id?, source?, included_quantity }
] }
source = { kind: "all_available" }
       | { kind: "source", source_key }
source_key = { kind, id, position }
```

선택 행은 최대20개, 수량 원문80자, 메모2000자이며 공통 HTTP16KiB 한도를 유지한다. 빈 배열은 명시적 I=0이다. 행이 있으면 빈 포함량은 미완성 오류이며 행을 생략하지 않는다. UUID·닫힌 중첩 필드·텍스트 제한을 기존 규칙으로 검증한다. 수량은 선택 관측 품목의 기준 단위이며 다른 원천 단위와 합하지 않는다.

원천 키는 실제 입고 또는 stable 관측과 행을 식별하고, 원천의 불변 버전은 후보·미리보기·확정 관계에 보존한다. 참조 관측은 해당 관측의 현재 유효 버전이어야 한다. 가장 최근 관측만 선택할 수 있다는 제한은 두지 않는다. 후보 조회와 확정 사이의 변화는 기존 전역 revision/CAS로 보호한다.

새 미리보기/결과 태그는 `reconciled_receipt`다. 실제 R/A, I/U, Ai/Au, Bv/D, 현재 품목별 전후 Q/V·dV, 별도 보정, 선택 근거와 후속 사건을 반환한다. 미리보기는 미래 UUID·시각을 생성하지 않는다. 확정 결과는 실제 receipt·settlement·holding 효과 관계를 반환한다.

`ReceiptDetail.holding_version_id`는 보정 입고에서 없거나 효과가 여러 개일 수 있으므로 nullable로 확장한다. 정상 입고는 기존 문자열을 그대로 반환한다. 추가 보정 상세는 정상 입고에서는 생략한다. U=0·dV=0이며 별도 보정만 있는 결과도 실제 입고로 조회할 수 있다. 의미 없는0수량 holding이나 관계없는 holding ID를 만들지 않는다.

## 3. 포함 몫의 중복 방지

원래 출처의 예약 한도와 선택 관측에 살아 있는 미예약 몫을 모두 검사한다. 일반 재실사는 앞선 출처를 승계하며 새 한도를 만들지 않는다. 선택은 기록 시각이 아니라 선택 관측의 계산 위치에 넣고, 기존 예약과 제안 예약을 함께 순서대로 재생한다. 더 과거의 새 선택이 이미 확정된 후속 예약을 침범하면 새 요청 전체를 거절한다. 기존 예약을 자동으로 줄이지 않는다.

가상 반례: 시작10 → 관측5 뒤 시작 위치에서5를 먼저 예약하면 후속 관측5의 예약/미예약 몫은 각각2.5다. 원래 미예약 한도5와 관측 전체5만 비교하여 새5를 허용해서는 안 된다. 선택된 과거 위치에서는 유효했지만 현재 소모·폐기된 수량은 계속 정산할 수 있고, 사용한 원래 예약 한도는 반환하지 않는다.

업무 수량·금액의 기존 fixed-point 계약은 유지한다. 단위가 달라지는 생산과 반복 평균 분할의 원천 지분 및 확인 가치의 반올림 전 잔여를 정확 유리수로 보존한다. 1000g에서 실사1g 소모·일반 입고1g를13회 반복하면 기존 원천 몫의 기약분자가 i128을 넘으므로, 단순 checked i128 분수로 정상 흐름을 차단하지 않는다. 이 내부 계산에는 `num-rational`의 `BigRational`을 사용한다. 클라이언트는 분수를 입력하지 않으며 서버가 검증한 원천 선택과 수량만 보낸다. [라이브러리 문서](https://docs.rs/num-rational/0.4.2/num_rational/type.BigRational.html)

원천 단위의 정확 지분과 선택 품목의 수량을 별도 타입으로 둔다. 표시 가능한 포함량은 기존 최소 단위로 보수적으로 표시하고 실제 중복 판정은 정확 지분으로 수행한다. 업무 수량·금액의 잔여 배분은 DOMAIN §2의 원순번·행순서·ID를 따른다.

관측의 미예약 몫 전체를 고르는 `all_available`와 특정 원천을 고르는 `source`를 구별한다. 예를 들어 두 원천에 각각0.5micro 단위가 남아 합계1micro인 관측은 전체 선택으로1micro를 확인할 수 있다. 서버가 해당 선택을 원천별 정확 지분으로 분할하고 영구 연결은 각 원천을 보존한다. 사용자 행을 최소 수량보다 작은 값으로 억지 분할하거나 새 원천을 만들지 않는다. 선택 행의 Bv/Ai와 원천별 부분 몫은 별도 필드다.

생산의 출처 분할은 가치 배분율과 구별한다. 투입/산출을 동일 품목별로 합산하고, 같은 기준 단위의 군 안에서는 실제 수량 비례, 서로 다른 단위군 사이는 균등한 무차원 비율을 사용한다. 입력의 원천 구성으로 각 결과물의 수량 몫을 만들고 취출한 원천 지분을 결과물 군/수량 비율로 나눈다. 모든 결과의 원천 지분 합과 각 결과의 수량 합을 보존한다. 이는 중복 예약을 위한 기술적 정규화이며 서로 다른 단위 사이의 물리 배합을 추정한 값이 아니다. 원가70:30/100:0·전부0원이어도 이 출처는 사라지지 않는다. 수량0인 행/군에 권리를 만들지 않으며 행 분할·순서·g/kg 환산 동치가 결과를 바꾸지 않는다.

## 4. 가치 계산

선택 관측 당시 저장된 가치/수량 비율로 Bv를 고정한다. 선택 관측 자체의 초과 원천을 직접 특정한 경우에만 해당 초과의 확인 가치/수량이 근거다. 과거 초과가 후속 관측이나 생산 결과로 승계된 몫은 선택 관측의 가치/수량 비율을 쓴다. 서로 다른 단위의 원천 가격을 선택 수량에 바로 곱하지 않는다. A는 먼저 I:U로 나눈 Ai/Au의 합을 보존하고, 이어 Ai를 선택 행 수량으로 최대 잔여 배분한다. D=Ai-Bv는 음수가 될 수 있다.

같은 관측을 여러 행·여러 확정으로 나누어 확인해도 Bv의 최소 단위가 중복되지 않게 한다. 그 관측의 이전/이번 선택이 가진 고정 비율의 정확 기대 가치를 합하여 한 번 반올림한 뒤, 이전 확정 Bv합을 빼서 이번 총량을 정한다. 이번 행에는 각 정확 기대 가치의 기여량으로 최대 잔여 배분하고 원천별 부분 몫까지 합을 보존한다. 직접 초과와 일반 잔량을 섞은 경우에도 관측별 잔여를 함께 확인한다. 이전 Bv는 재작성하지 않는다. 명시0 선택은 참조를 확인하고 금액/예약0으로 보존한다.

1. 일반 입고 R/A, 과거 보정의 U/Au, 생산·관측·폐기를 원순번으로 구성한다. 과거 보정의 현재 dV와 별도 보정은 재생 유입으로 다시 가산하지 않는다.
2. Base에는 기존 유효 포함 연결의 고정 Bv→Ai를 각 선택 관측 위치에서 한 번 적용한다. Base의 현재 Q/V가 실제 holding과 같아야 한다. 불일치를 새 보정으로 흡수하지 않는다.
3. Proposed에는 이번 선택을 추가한다. 후속 실제 수량·실사 확정 소모·생산 행/배분율은 고정하고 평균 원가·잔여 규칙으로 가치만 계산한다.
4. 품목별 dV는 Proposed.V-Base.V다. 별도 보정은 D-ΣdV이고, 현재 순증 Au+ΣdV와 합하여 A-Bv가 되어야 한다.
5. 현재 입고 품목에 U/Au를 한 번 추가한다. Q=0에는 V=0만 허용하며 각 최종 가치가 음수이면 입력과 상태를 보존하고 근거 확인을 요구한다.

후속 초과의 이미 확정한 금액과 단가 출처는 고정한다. 가상 Q10/V10 뒤 초과5를 가치5로 확인한 상태에서 앞 관측에 D5를 넣으면 현재 V20이다. 후속 초과를 단가1.5로 다시 평가해 V22.5로 만들지 않는다. 해당 확인 입력의 정정은 T-012의 유효 개정 대체 범위다.

서로 다른 관측에 연속 보정할 때도 새 Bv는 그 선택 관측의 저장 근거를 사용한다. Q10/V10 → Q5/V5 뒤 옛 관측5몫의 Bv5→Ai10 보정으로 현재V7.5가 되었더라도, 이전 Q5/V5 관측의 남은2.5몫은 Bv2.5다. 이후 실제 새 관측 Q5/V7.5를 선택할 때만 해당2.5몫의 Bv3.75를 사용한다.

생산은 기존 투입 품목별 합계 평가·행별/결과별 최대 잔여를 재사용한다. 부분 폐기는 V를 남기고 전량 폐기는 남은 가치를 종료한다. 과거 실사 K/판매 배분·생산 금액·판매 당시 원가·원요청/원응답/JSON을 덮어쓰지 않는다.

## 5. 저장과 호환성

format2/schema11에서 실제 입고, 포함 연결의 불변 버전/현재 head, 정산, 품목별 보유 효과와 별도 보정을 한 transaction으로 저장한다. 실제 R을 기준으로 주문을 한 번 종료한다. 유효 링크를 각각 한 번만 선택하고 관측/원천/품목/시점·예약·금액 보존을 동일 순수 계산으로 검증한다.

holding의 새 보정 원천은 수량 U와 Au/dV를 구별하며 실제 관측·확인 시각을 새로 만들지 않는다. 기존 기준을 승계하고 보유 평균과 last_valid를 정상 규칙으로 갱신한다. receipt 한 건당 holding 한 건이라는 옛 가정은 일반 입고에만 적용한다.

schema10 frozen reader는 이전 일곱 업무 종류, 옛 입고 중첩 태그, 네 holding 원천, 실사·폐기의 이전 구조를 닫는다. 정상 API로 만든 schema10 fixture와 모든 원요청/응답/JSON 바이트를 보존한다. 새 태그·보정 필드를 source10에 끼워 넣은 자료는 변환 전에 거절한다.

holding 테이블을 재구성할 때 heads·sale_cost_rows·stocktake_versions·wastes의 FK를 함께 보존한다. FK 비활성화로 우회하지 않는다. 이전 버전 백업·원자 migration·foreign_key_check·실패 시 원본 보존을 검증한다. 동일 성공 UUID 재생은 현재 후보/예약/CAS 검사보다 먼저 처리한다.

## 6. 화면과 오류

기존 입고 화면에 명시적인 실사 포함 모드를 추가한다. 품목별 관측과 원천 근거를 조회해 사용자가 선택하며 수동 UUID 입력을 요구하지 않는다. 일반 실사·초기·초과, 이미 사용된 근거도 의미를 구별해 표시한다. 후보 조회 실패·늦은 응답·품목 변경으로 입력을 자동 교체하거나 포함량을 줄이지 않는다.

실제 구입 정보 → 실사 포함/현재 추가 수량 → 현재 품목별 가치 변화 → 이미 사용된 부분의 별도 보정 → 원기록 링크 순으로 보여준다. 부호·0·null을 구별하고 화면에서 원가를 다시 계산하지 않는다. 여러 품목은 각 단위를 유지한다. 유효한 실제 관계로만 링크하며 관측 버전/holding ID로 URL을 추정하지 않는다.

선택 배열·baseline·pending은 깊은 복사한다. 중첩 변경은 dirty와 미리보기 무효화에 반영한다. 불확실 요청은 후보가 이후 사라져도 원 UUID/action/body로 재시도한다. 409는 입력을 보존한 재검토, 413은 명시적인 본문 검토로 안내한다. 새 모드 전환은 사용자의 명시 동작이다.

기존 테마·글꼴·탐색을 유지한다. 1440/768/390 너비와 두 테마, 행 추가/삭제 포커스, 키보드 선택·미리보기·확정, 정상 종료/재시작과 두 탭 충돌을 실제 검증한다.
