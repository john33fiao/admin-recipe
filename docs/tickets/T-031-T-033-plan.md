# T-031~T-033 공통 설계·구현 계획

2026-10-25. [ADR-010](../decisions/ADR-010-unified-bulk-entry.md)의 위임받은 기술 설계다. CSV 업로드·직접 시트 입력·확인 화면 편집을 하나의 입력→확인→등록 흐름으로 만든다. 원 티켓의 수용 기준은 각각 유지한다.

## 변경 전 RTD — 세 티켓 각각에 적용

- [Step 1] 변경 계획 - PASS: 재료·메뉴·입고의 양식/표/수정/확인/등록·조회와 오류·재시도·부분 성공·지연 입고·복원을 검증한다. frontend의 bulk 타입/CSV/검증/순차 실행/입력 보존/표/페이지, Rust 읽기 전용 입고 미리보기와 관련 시험·문서를 변경한다.
- [Step 2] 계획 검토 - PASS: 기존 UUID·버전·6자리 숫자·단위·epoch·JSON writer를 사용한다. 입고 초안의 저장과 실제 확정을 구별하고 실사 포함량을 자동 재가산하지 않는다. 공개 자료는 가상이며 시험·시연·운영 DB를 분리한다.
- [Step 3] 검토 재검토 - PASS: 주요 가정은 CSV 선택(티켓의 '또는'), 메뉴 그룹을 실제 레시피로 저장, 입고별 독립 미리보기와 후속 효과 변경 시 명시 재확인이다. 같은 품목의 여러 정상 입고를 금지하거나 이름으로 자동 병합하지 않는다.
- [Step 4] 계획 단순화 - PASS: xlsx·범용 시트 라이브러리·새 batch 스키마/직접 writer 없이 기존 input/select·API·검증/보존을 재사용한다. 세 티켓을 별도 UI로 중복 구현하지 않는다.

## 파일과 인터페이스

| 담당 | 변경/검증 |
| --- | --- |
| CSV·표 입력 | `frontend/app/utils/bulk-csv.ts`, `types/bulk.ts`, `components/BulkSheet.vue`: 엄격한 CSV·한글 표시·문자열 값·행 추가/삭제·붙여넣기·Tab |
| 확인본·실행 | `utils/bulk.ts`, `utils/bulk-runner.ts`, `composables/useBulkEntry.ts`: 필수값/UUID·버전 고정·그룹·경고·확인 무효화·행별 결과/불명 요청/재시도 보존 |
| 화면·탐색 | `pages/bulk.vue`, 공통 탐색/보존 입력: 대상별 양식·업로드/직접 입력·수정·최종 확인·등록·상세 링크 |
| 입고 읽기 | `src/receipt.rs`, `src/store/receipt.rs`, `src/server.rs`: `POST /api/receipts/preview`의 `{state:{epoch,revision},data}`를 closed DTO로 받고 기존 `normalize_receipt_draft`·`inspect_receipt` 사용 |
| 쓰기 경로 | 기존 `/api/materials`, `/api/recipes`, `/api/business/drafts`→업무 preview→confirm. 새 직접 적재 없음 |
| 시험 | `frontend/tests/bulk*.test.ts`, `frontend/e2e/bulk.spec.ts`, `tests/receipt_http.rs`: 아래 입력군·실제 저장/오류·재시도/복원 |

읽기 전용 입고 응답은 `{state,can_confirm,issues,effect}`다. 중첩 state도 미지 필드를 거절하고 canonical UUID·revision을 검증한다. 현재 세대와 다르면 stale_generation/not_processed, 개정이 다르면 stale_state로 거절한다. 정상 결과와 오류 모두 초안·seq·원문·파일을 쓰지 않는다. `recover`·`mutate`를 호출하지 않으며 writer mutex의 한 closure 안에서 상태 대조와 계산을 수행한다.

## 구현 순서와 검증

- [x] CSV 구문/열/크기·행 상한, 0/빈 값, 메뉴 그룹·단위/참조 오류의 실패 시험을 먼저 실행하고 최소 파서·검증을 구현한다.
- [x] 순차 실행·원 UUID 보존·부분 성공·효과 변경 정지·복원/세대 충돌의 실패 시험 뒤 실행기를 구현한다.
- [x] 입고 무기입 preview HTTP 실패 시험 뒤 기존 inspector를 연결한다. 정상/미완성/0원/포함입고·상태/Origin/세션/16KiB·DB/원문 bytes 불변과 기존 preview 효과 동등성을 확인한다.
- [x] 공유 편집표·업로드·직접 입력·수정/취소·오류 위치·확인/등록·결과 링크와 입력 보존을 연결한다.
- [x] frontend 입력을 동결하고 `node scripts/build.mjs`로 갱신한 뒤 UI 단위/타입·관련 Cargo와 실제 Chromium을 실행한다. 최초 실패·수정·후속 결과와 겹치는 시험 수를 분리한다.
- [x] 세 티켓별 수용 기준과 After13·요구/색인/실제 Obsidian 연결 노트 대응을 확인한다. 승인 범위의 공개 파일만 검토·논리 커밋한다.
- [x] T-021의 실행 가능한 전체 회귀·release 규모별 비용·공개 경계를 통합하고 필수 외부05 미검증을 구분했다. T-021·전체 goal의 미완료 조건은 유지한다.

## 검토 초점과 실제 UI 시나리오

1. 재료 CSV 양식→인용 쉼표/줄바꿈→오류 수정→확인 전 쓰기0→최종 수정본 등록/조회. 형식·상한·미지/중복 열도 거절한다.
2. 파일 없는 행 추가/삭제·붙여넣기·Tab·취소·reload 입력 보존. 1440/768/390px 라이트/다크와 오류 셀 연결을 확인한다.
3. 메뉴 그룹의 여러 구성·기준 개수·없음/0원 판매가·UUID/버전과 실제 레시피 조회. 동일 이름을 자동 병합하지 않는다.
4. 입고 수량/금액 수정·0원/빈 값·입고일/입력 시각·등록 전 읽기와 정상 확정/JSON을 확인한다. 0수량 입고를 새로 허용하지 않는다.
5. 재료/입고 확정 응답 유실→reload→동일 UUID/본문 확인→중복0·성공 행 생략. 저장소 보관 실패 때 전송0, 전송 중 편집/늦은 응답도 다룬다.
6. 실사 포함 지연 입고의 선택→미리보기→확정으로 포함량 재가산0·중복 몫 거절/입력 보존을 확인한다.
7. 외부 개정 또는 앞선 같은 품목 입고로 효과 변경→해당 행 정지→성공 행 보존→새 효과 명시 재확인 후 이어 등록. 재업로드와 명시 새 입력도 구분한다.
8. 다른 탭의 전체 복원 뒤 bulk 초안/불명 요청을 보존하고 자동 재적용0·already_processed 거절·보존 입력 조회를 확인한다.

원문/사진/무기한 기록 검사를 생략하거나 자료를 지워 성능을 숨기지 않는다. T-001 별도 깨끗한 장비·실제 절전·다운로드/서명과 T-027 OS 왕복은 이 구현으로 완료 처리하지 않는다.
