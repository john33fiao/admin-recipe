# T-017: 발주·입고·마지막 실사 중심 운영 개요

- 상태: 완료 — 마지막 확인·논리 변동·전체 목록·키보드 검증
- 단계: 1차
- 작성일: 2026-10-24
- 관련 요구: D-01~D-03·D-09, P-05·P-06·P-08
- 선행: [T-006](T-006-purchase-orders.md), [T-007](T-007-receipts.md), [T-015](T-015-photos-and-suppliers.md), [T-016](T-016-statistics-and-history.md)
- 기준: [요구사항](../REQUIREMENTS.md), [최신 운영 결정](../decisions/ADR-007-consumption-and-ticket-scope.md)

## 목적

현재 확인된 운영 상태와 다음에 입력할 기록을 한 화면에서 파악한다.

## 포함 범위

미입고 주문·최근 입고, 품목별 마지막 확인 수량/시각과 이후 확정 변동, 최근 판매·소모·폐기·실사 차이의 요약 화면을 만든다.

## 제외 범위

내일 제공 가능 메뉴·추가 발주 시뮬레이션·시설 점검.

## 수용 기준

- [x] T-017-01: 별도의 예상 현재고를 계산하거나 판매 가능한 재고처럼 표시하지 않는다. 마지막 실사 수량과 확인 시각을 함께 표시한다.
- [x] T-017-02: 이후 입고·생산·반품·폐기 변동은 마지막 실사와 구별해 조회할 수 있다. 미입고 주문량은 실물 보유량에 합치지 않는다.
- [x] T-017-03: 주문 종료 차이·미배분 소모·소모 미확정 판매·미완료 입력의 의미를 구분한다.
- [x] T-017-04: 요약 수치에서 근거 목록/상세로 이동하고 판매 입력·실사 등 주요 작업을 시작한다.
- [x] T-017-05: 1차에 없는 내일 메뉴 계획이나 시설 점검 결과를 구현된 것처럼 채우지 않는다.
- [x] T-017-06: 빈 데이터·오류·오래된 실사·긴 목록에서도 판단에 필요한 상태가 명확하다.

## 검증 방법

가상 주문→입고→판매→실사 시나리오에서 요약/상세 일치, 예상 재고 부재와 미입고 분리, 빈/오류 상태 UI 검증.

구현 티켓은 [공통 완료 조건](README.md#공통-완료-조건)의 실제 명령에서 영향 범위를 선택한다. 후속 구체화 티켓은 먼저 미결정을 확정하고 구현·검증 작업을 나눈다.

## 남은 결정과 구현 메모

운영 정책 질문은 확정됐다. 화면 구성·스키마·오류 표시·정밀도 등은 T-002와 기존 구조에 맞춰 설계한다. 새 운영 판단이 필요하면 예시와 영향을 제시하고 해당 부분만 보류한다.
