# T-021 의존성·입력 경계 검토

2026-10-25, 현재 Mac 개발 환경에서 실행한 검토다. T-001의 실환경 배포 조건과 T-021의 최종 완료는 별도다. 일괄 입력 추가 뒤 영향을 받는 경계를 다시 확인한다.

## 범위와 변경 전 검토

- [Step 1] 변경 계획 - PASS: 잠금 파일의 출처·무결성, 현재 보안 권고와 사용 경로, 세션/Origin·파일/사진·복원·일괄 입력·공개 자산을 대조한다. 새로운 의존성이나 보안 정책을 임의로 추가하지 않는다.
- [Step 2] 계획 검토 - PASS: 공식 npm 보안 조회는 사용자 승인 뒤 수행했다. Rust 권고 DB는 공개 전체 자료를 받아 로컬에서 대조했다. 운영 자료·인증자료는 조회에 포함하지 않았다.
- [Step 3] 검토 재검토 - PASS: 감사 도구의 의존 경로 건수와 독립 취약점 수, 개발 도구와 실제 배포 경로, 정적 검토와 실행 시험을 구분한다.
- [Step 4] 계획 단순화 - PASS: 현재 잠금 파일과 기존 경계 검증을 재사용한다. 취약점 수를 줄이기 위한 프레임워크 다운그레이드나 검증 생략은 하지 않는다.

| 명령/대상 | 결과 |
| --- | --- |

RustSec 자료 기준은 커밋 `21d909e4c8bd4e14c7aea58bf980c881a0053ab1`, 2026-10-24 갱신이다. 이는 조회 시점 권고 대조이며 알려지지 않은 취약점이 없다는 보장은 아니다. 도구는 Git 제외 임시 폴더에 설치했고 전역 PATH·설정은 바꾸지 않았다.

최초 npm 조회는 제한 환경의 DNS 실패였고, 외부 의존성 메타데이터 전송 권한 검토도 한 번 거절됐다. 사용자에게 이유를 설명하고 공식 npm 조회 승인을 받은 뒤 다시 실행했다. 실패를 통과로 세지 않았다. `cargo metadata --locked --offline`의 전체 타깃 조회는 캐시에 없는 타깃용 `core_detect` 때문에 실패했으며, 현재 Mac 대상의 실제 build/test 결과와 구분한다.

## 남아 있는 npm 권고와 사용 범위

설치된 `node-forge`1.4.0은 RSA PKCS#1 v1.5 서명 검증의 중첩 DigestAlgorithm 검사 취약점 [GHSA-86w9-cpqp-85rv / CVE-2026-85393](https://github.com/advisories/GHSA-86w9-cpqp-85rv)의 영향 버전이다. 공식 권고는 2026-10-01 갱신 기준 패치 버전을 제공하지 않는다. npm의7건은 `node-forge`와 `listhen`·`nitropack`·Nuxt 관련 상위 의존 경로를 합친 수이며 독립 취약점7개로 표현하지 않는다.

현재 설치 코드의 `listhen` 경로는 개발 HTTPS용 키/인증서 생성·PKCS12 읽기를 제공한다. 해당 호출부에서 취약한 RSA 서명 검증 호출은 발견하지 않았다. 프로젝트의 표준 생성은 정적 SPA를 만들며 배포 실행은 Rust 서버가 담당한다. 생성된 공개 UI에서 `node-forge`가 발견되지 않은 점도 확인했다. 이 근거는 현재 배포 요청 경로에서 해당 Node 라이브러리를 실행하지 않는다는 판단을 뒷받침한다. 개발 도구의 취약 의존성이 제거됐다는 뜻은 아니다.

`npm audit`가 제시한 Nuxt4.1.3 다운그레이드를 자동 적용하지 않았다. 현재 스택·잠금 파일을 유지하고 수정 버전 또는 의존 경로 제거가 가능한지 후속 검토할 잔여 항목으로 남긴다. 원격 개발 서버·HTTPS·새 서명 검증 기능을 추가할 때 사용 범위를 다시 평가한다.

## 애플리케이션과 공개 경계

- 기존 `src/server.rs`의 정확한 Host/Origin·실행 세션 쿠키·loopback, 전체 저장 mutex와 종료 대기를 유지한다. 비밀번호나 네트워크 공동 사용은 추가하지 않는다.
- 사진은 기존 JPEG/PNG 실제 decode·hash·크기·no-follow·불변 게시를 유지한다. 복원은 원문64MiB·닫힌 target·중복 JSON key/미래 schema·참조·사진 전체 검사를 유지한다.
- 공개 코드·시험·양식에는 가상 자료만 사용한다. 지정 시연 자료·DB·화면·API 원문은 Git 제외 경로에 보존한다. 생성 UI·release의 개인 경로 검사는 표준 빌드에 포함한다.
- 일괄 입력은 기존 정상 writer·원요청·버전·JSON·복원 계약을 사용한다. UTF-8 fatal decode·1MiB/200행·닫힌 헤더/열·텍스트 표시와 전송 전 원요청 보존, 부분 성공·외부 초안·복원 세대 경계를 독립 검토했다. 최종 UI165·입고 HTTP12(신규4)·실제 bulk 브라우저13을 [관련 검증](T-031-T-033-verification.md)에 대응했다.
- 새 입고 미리보기는 같은 mutex에서 세대/개정·닫힌 입력을 검사하고 기존 inspector를 호출한다. HTTP 시험은 전체 DB/파일 바이트 불변, 누락 JSON 재발행0, Origin/세션·16KiB·정확한 경로를 확인했다. 일반16KiB와 기존 레시피256KiB 등 API별 상한을 유지한다.
- 복원된 UUIDv8 entity 참조를 허용하되 새 mutation UUIDv4 계약은 유지했다. 성공행/불명 원본문 잠금, 탭 보관 실패 전 전송0, 늦은 응답·복원 뒤 이미 처리된 요청 재적용0을 단위·실제 UI로 확인했다.

최종 release의 `file` 결과는 ARM64 Mach-O다. `otool -L`은 OS 제공 프레임워크/라이브러리6개만 가리킨다. `codesign -dvv`에는 linker의 ad-hoc 서명과 `TeamIdentifier=not set`이 표시된다. 이는 개발 장비 산출물의 속성 확인이며 정식 배포 서명·공증·다운로드 실행이나 별도 깨끗한 Mac 검증을 대신하지 않는다.

세션·파일·사진·복원 회귀와 최종 공개 후보 검토의 실제 결과는 [T-021](../tickets/T-021-first-release-verification.md)에 연결한다. 이 검토는 확인한 변경 경계에 대한 판단이며 전체 배포 준비를 완료 처리하지 않는다.

## 최종 검토 결과

현재 Mac의 실제 Rust631개가 실패0·무시0으로 종료했고 최종 UI165·타입/정적·자산 경계, 새 bulk13개를 확인했다. 기존 브라우저는 같은 후보에서119통과/3관측실패였고 기본 timeout·원단언을 유지한 후속3개가 통과했다. 각 후보·고유 범위와 최초 실패는 통합 기록을 따른다. native select의 Mac headless 화살표 키는 독립 HTML에서도 동작을 확인하지 못해 두 시험의 선택 준비에 `selectOption`을 사용했다. 뒤의 실제 Tab/Enter·Space·재시작/6화면 단언은 유지했고 native 물리 키 선택 성공으로 확대하지 않는다.

최종 전체 업무48·시연 보존 복사본 읽기10과 release 두 규모 자료의 정상 저장/조회·재시작·모든 JSON 보존을 확인했다. 사전 입력을 직접 DB에 적재하거나 원문/무결성 검사를 줄이지 않았다. 공개 후보는 UTF-8/LF·상대 링크·제외 규칙·개인 자료/경로·실제 diff를 검토한다. npm 단일 권고의 High7 전파 경로는 여전히 남아 있으며 수정·감사 전체 무경고를 주장하지 않는다. 실제 볼트 대응과 필수 외부 미검증은 별도로 기록한다.
