# 요구사항

2026-10-24 기준의 기획 초안이다. 확인된 요구와 검토 중인 정책을 구분한다. 구현 완료나 첫 버전의 전체 범위를 의미하지 않는다.

## 목적

셰프 1명이 레시피·발주·입고·판매·재고·일일 점검을 관리하고, 현재 재료와 입고 예정량으로 다음 날 준비할 메뉴와 수량을 파악한다.

## 확인된 요구

| 영역 | 요구 |
| --- | --- |
| 재료 | 이름과 별개인 고유 ID로 식별하고 단가를 관리한다. |
| 단위 | 기본값은 g이며 mL·개·장 등을 재료 종류와 무관하게 선택한다. 레시피는 재료의 관리 단위를 따른다. |
| 손질 | 원물과 손질 완료 재고를 구분한다. 손질 상태별 조회가 필요하다. |
| 레시피 | 메뉴에서 재료·분량·시간·식재료비를, 재료에서 사용하는 메뉴를 찾는다. |
| 설명 | 재료·메뉴의 사진과 간단한 설명, 주요 구입처 링크·설명을 입력하고 조회한다. |
| 발주·입고 | 주문량·실입고량·현재 재고·예상 재고를 구분한다. |
| 판매 | 메뉴별 판매 수량을 직접 입력한다. POS 연동은 현재 범위에서 제외한다. |
| 재고확인 | 정기 확인을 통해 예상 소진량과 실제 차이를 파악한다. 메뉴별 실제 사용량의 일일 입력은 요구하지 않는다. |
| 원가 | 첫 버전은 식재료비를 대상으로 한다. 포장재·소모품·인건비는 이후 확장한다. |
| 메뉴 계획 | 보유 재료와 입고 예정량에 따른 메뉴·수량, 추가 발주 후의 가용량을 확인한다. |
| 작업시간 | 비정기적으로 측정한 시간을 사후 기록하고 시계열로 조회한다. 첫 버전 포함 여부는 미정이다. |
| 시설 점검 | 카테고리·하위 항목을 설정하고 매일 완료 처리한다. 첫 버전 포함 범위는 미정이다. |
| 화면 | PC·태블릿·모바일 웹과 라이트·다크 테마를 지원한다. |

## 주요 미결정 항목

식별자는 기획 검토의 연속성을 위해 유지한다. 모든 항목은 별도 결정 전까지 미정이다.

| ID | 결정할 내용 |
| --- | --- |
| C-01 | 같은 재료 아래 상태를 둘지, 손질재료·반제품에 별도 품목 ID를 둘지 |
| C-02 | 판매·조리·손질 중 어떤 기록이 어떤 재고를 차감하는지 |
| C-03 | 손질 투입·확보량을 실측할지, 표준 수율과 정기 확인을 사용할지 |
| C-04 | 운영 사례의 배분량이 원물 기준인지 손질 후 기준인지 |
| C-05 | 서비스 이관 시 원본 자료와 대조할 기준값·단가·생산량 |
| D-01 | 첫 버전 기능과 우선순위 |
| D-02 | 판매 합계 수정·추가분 누적·영업일 마감 |
| D-03 | 재고확인 주기·대상·소진 차이 표시 기준 |
| D-04 | 원가 적용 단가·평균 기간·수율·부산물 비용 배분·판매가 기준 |
| D-05 | 단위 추가·변경·포장 환산·소수 정밀도 |
| D-06 | 작업시간 측정 범위·표준시간·배치·설비 조건 |
| D-07 | 시설 점검 입력 형식·설정 변경 시점·휴무·해당 없음 |
| D-08 | 부분 입고·취소·반품·폐기·판매 외 소진·입고 마감 |
| D-09 | 검색·사진·설명·구입처·반응형·테마·빈 화면·오류 상태 |
| D-10 | 다중 사용자·매장·권한·유료 서비스 범위 |
| D-11 | 파일 또는 DB, 사진 저장 위치, 기기 간 공유 |
| D-12 | 호스팅과 외부 접속 방식 |
| D-13 | 인증·데이터 권한·계정·백업·복원 |

## 설계 자료의 위치

화면 초안은 요구를 검토하기 위한 참고 자료다. 초안의 예시 수치와 임시 정책을 확정 요구로 취급하지 않는다. 사진·설명·구입처 정보는 화면 초안 이후 추가된 요구로서 구현 전에 반영 여부를 확인한다.

운영 자료 원본과 비공개 화면 링크는 공개 문서에 복사하지 않는다. 공개 저장소만 읽는 기여자가 작업할 수 있도록, 구현에 필요한 확정 사항과 수용 기준은 검토 후 공개 문서·티켓에 작성한다.
